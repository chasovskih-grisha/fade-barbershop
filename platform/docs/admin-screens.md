# Екрани адмінки — управління мережею

> Специфікація екранів `apps/admin` для управління локаціями, барберами, послугами/цінами, годинами роботи, **календарем мережі, картками клієнтів, знижками, листом очікування, кампаніями і галереєю**. Кожен екран має посилання на приймальні критерії `acceptance-criteria/04-admin-management.md` (MNG-ADM-*) та суміжні (REF-ADM, PAY-ADM, LYL-ADM, DSC-ADM, FDB-ADM, NSH-ADM, WTL-ADM, WNB-ADM, PRT-ADM).
>
> Роль у v1 — єдина: `admin` (засновник). Desktop-first: звичайний монітор, миша, клавіатура. Всі мутації — через API, не через Prisma з цього пакета.

## Оболонка (shell)

- **Sidebar** (ліворуч, фіксований): Локації · Персонал · Календар · Клієнти · Послуги · **Знижки** · Відгуки · **Лист очікування** · **Кампанії** · **Реферали** · **Галерея** · **Сертифікати** · **Товари · Замовлення** · Оплати · Блог · Налаштування. Активний розділ підсвічений.
- **Header** (зверху): фільтр локації (Мережа / CLT-01 / …), ім'я адміна, «Вийти».
- Загальні правила: таблиці з фільтр-баром і кнопкою створення; порожні стани з поясненням і CTA; деструктивні дії — confirmation; помилки валідації — українською біля поля; помилка API — банер з кнопкою «Повторити»; завантаження — скелетони замість таблиці.

## 1. Локації (`MNG-ADM-01…04`)

### 1.1 Список «Локації»

- **Layout**: заголовок + кнопка «Створити локацію» → фільтр-бар (Статус: Всі/Активна/Вимкнена) → таблиця.
- **Колонки**: Код | Назва | Адреса | Години роботи (скорочено: «Пн–Пт 09:00–20:00 · Сб 10:00–18:00») | Крісла (`2/2`) | Статус (бейдж) | Дії (Редагувати · Вимкнути/Увімкнути).
- **Порожній стан**: «Локацій ще немає — створіть першу», кнопка «Створити локацію».
- **«Вимкнути»** → confirmation: «Локація стане недоступною для нових записів. N активних візитів не скасовуються.» Кнопки: «Вимкнути» / «Скасувати» (`MNG-ADM-02`).

### 1.2 Форма локації (створити / редагувати) — сторінка з двома секціями

**Секція «Дані локації»** (`MNG-ADM-01`):
| Поле | Тип | Валідація |
|------|-----|-----------|
| Код | text, uppercase | обов'язковий, унікальний (серверна перевірка, помилка біля поля: «Код уже зайнятий») |
| Назва | text | обов'язкова |
| Адреса | textarea | обов'язкова |
| Координати | lat/lng + міні-карта для вибору точки | обов'язкові (для карти на сайті) |
| Контакти: телефон, email | text | опційно, формат перевіряється |
| Логотип | light (обов'язковий) + dark (опційно) файли, варіант `mark`/`lockup`, alt | alt обов'язковий і не порожній; публічний бакет `location-brand` (T-4609) |
| Активна | toggle | — |

**Секція «Години роботи»** — див. 1.3. Кнопки: «Зберегти» / «Скасувати».

### 1.3 Редактор годин роботи локації (`MNG-ADM-03`)

- **Layout**: 7 рядків (Пн…Нд): checkbox «Вихідний» + два time-інпути «Відкриття» / «Закриття» (15-хв крок).
- **Валідація**: «Відкриття» < «Закриття»; порожній час без «Вихідного» — помилка рядка.
- Після «Зберегти» години одразу видно на сайті і в додатку.

### 1.4 Крісла (`MNG-ADM-04`)

- **Layout**: підсекція на сторінці локації: список крісел (№ · Назва (опційно) · Активне toggle).
- Неактивне крісло не бере участі в розкладі (позначка «Неактивне»).

## 2. Барбери (персонал) (`MNG-ADM-05…09`)

### 2.1 Список «Персонал»

- **Layout**: заголовок + «Додати барбера» → фільтр-бар (Локація: Всі/…, Статус: Всі/Активний/Деактивований) → таблиця.
- **Колонки**: Ім'я | Телефон | Локації (chips: CLT-01) | Графік (скорочено: «Пн–Пт 10:00–19:00») | Статус (бейдж) | Дії (Редагувати · Графік · Деактивувати/Активувати).
- **Порожній стан**: «Барберів ще немає».

### 2.2 Форма барбера

| Поле | Тип | Валідація |
|------|-----|-----------|
| Ім'я | text | обов'язкове |
| Телефон | tel, `+380…` | обов'язковий, унікальний (той самий `User`, роль `barber`; пароль не потрібен — OTP, ADR 0005) (`MNG-ADM-05`) |
| Локації | checkbox-список | ≥ 1; можна кілька (`MNG-ADM-06`) |
| Активний | toggle | — |

- **Деактивація** → confirmation: «Барбер не отримуватиме нових записів. N існуючих візитів лишаються.» (`MNG-ADM-05`).

### 2.3 Редактор графіка барбера (`MNG-ADM-07…09`)

- **Layout**: 7 рядків (Пн…Нд); кожен — toggle «Вихідний» або список вікон прийому (кожне: «з»–«до», кнопка видалення) + «Додати вікно» (макс. 2 на день, 15-хв крок).
- **Валідація**: вікна не перетинаються в межах дня (помилка рядка).
- **При збереженні** (конфлікти з існуючими візитами, `MNG-ADM-08`): модальне вікно «Конфлікти графіка» — список постраждалих візитів (клієнт · час · послуга), на кожен вибір: «Перенести» (вибір нового слота) або «Лишити як є». **Збереження блокується, доки не вирішені всі конфлікти.**
- **Self-service** (фаза 22): якщо барберу делеговано графік (`SCH-001`), той самий агрегат `Availability` редагує і барбер з mobile — з жорсткішими обмеженнями (в межах `OpeningHours`, без права переносити клієнтів при конфліктах); адмінський редактор залишається старшим джерелом (`SCH-006`). Запити «повідомити адміна» від барбера відкривають цей редактор з підсвіченими конфліктами (`SCH-ADM-03`).
- **Cross-check з годиною роботи локації** (`MNG-ADM-09`): якщо графік барбера виходить за `OpeningHours` — жовтий банер-попередження (не помилка): «Години барбера виходять за години роботи локації».

## 3. Послуги і ціни (`MNG-ADM-10…14`)

### 3.1 Список «Послуги»

- **Layout**: заголовок + «Створити послугу» → фільтр-бар (Категорія, Статус) → таблиця.
- **Колонки**: Назва | Категорія | Тривалість (хв) | Ціни (chips по локаціях: «CLT-01 · 400 ₴») | Статус (бейдж) | Дії (Редагувати · Ціни · Вимкнути).
- **Порожній стан**: «Послуг ще немає».

### 3.2 Форма послуги (`MNG-ADM-10`)

| Поле | Тип | Валідація |
|------|-----|-----------|
| Назва | text | обов'язкова |
| Опис | textarea | опційний |
| Категорія | select (стрижка, гоління, борода, догляд) | обов'язкова |
| Тривалість | number, хв | обов'язкова, 10–240 |
| Активна | toggle | — |

**Секція «SEO і FAQ»** (фаза 26, `SRV-ADM-01`):

| Поле | Тип | Валідація |
|------|-----|-----------|
| Slug | text | унікальний, автогенерація з назви; зміна редагованого → 301 зі старого |
| `<title>` / meta description | text | шаблон з автопідстановкою або вручну (перекриває шаблон) |
| FAQ | список 3–6 пар «питання → відповідь» | draggable порядок; рендериться на сторінці послуги з `FAQPage` розміткою |

- **«Вимкнути»** → confirmation: «Послуга не показуватиметься в записі на всіх локаціях.» Сторінка `/services/{slug}` зникає (410, SRV-007).

### 3.3 Матриця цін по локаціях («Ціни» на послугу) (`MNG-ADM-11…14`)

- **Layout**: таблиця: Локація | Ціна (UAH, числовий інпут, inline-редагування) | Доступна (toggle — ввімкнено/вимкнено для конкретної локації, `MNG-ADM-12`).
- Одна послуга, різні ціни на різних точках — видно одним екраном (`MNG-ADM-11`).
- **Зміна ціни** → confirm-banner: «Зміна застосується лише до нових записів. N візитів зі старою ціною не зміняться.» (`MNG-ADM-13`).
- **«Історія змін»** — панель на цьому ж екрані: дата · адмін · «400 ₴ → 450 ₴ (CLT-01)» (`MNG-ADM-14`).

## 4. Години роботи (зведено)

Окремих екранів немає — години живуть у двох місцях:

| Що | Де редагується | Критерій |
|----|----------------|----------|
| Години роботи локації (`OpeningHours`) | 1.3, на сторінці локації | `MNG-ADM-03` |
| Графік барбера (`Availability`) | 2.3, на сторінці барбера | `MNG-ADM-07…09` |

Зведений «Графіки»-перегляд у календарі (фаза 4) — пізніше, за потреби.

## 5. Календар мережі (`MNG-ADM-15`, REF-ADM-01…04)

### 5.1 Календар (день / тиждень)

- **Layout**: тулбар → сітка. **Тулбар**: перемикач День/Тиждень, фільтр локації (Мережа/CLT-01…), фільтр барбера, фільтр «З референсом / Без референсу / Усі» (REF-ADM-02), кнопка «Сьогодні».
- **Сітка**: колонки = барбери (або крісла, інваріант 2), рядки = час (15-хв крок); комірки = візити.
- **Комірка візиту**: клієнт, послуга, час; статус оплати (бейдж, PAY-ADM-01); бейдж «Безкоштовно» для 7-го візиту (LYL-ADM-05); маркер «є референс» (іконка фото). Партія `father-son` — зв’язані блоки на одному або двох стовпцях (`PARTY-ADM-01`).
- **Клік по комірці** → картка візиту (модальне вікно/панель праворуч, див. 5.2).
- **Клік по вільному слоту** → «Створити візит (walk-in)» — швидка форма: послуга, клієнт (пошук/новий), час (за замовчуванням «зараз»), коментар (опц.) (WALK-ADM-01); далі — оплата на місці (WALK-ADM-02).
- **Порожній стан**: «На цю дату візитів немає». Конфлікт слотів неможливий (інваріант фази 4).
- **Waitlist-hold**: слот, утриманий пропозицією черзі, показується штрихованим з підписом «Очікує підтвердження (хв)» і не доступний для кліку-створення (`WTL-003`, ADR 0012).

### 5.2 Картка візиту

- **Деталі**: клієнт (посилання на картку, розділ 6), локація, барбер, час, послуга, статус візиту і оплати.
- **Референс зачіски**: мініатюра → повний розмір (клік), поруч — оригінальне фото клієнта (якщо референс з AI) і коментар (REF-ADM-01). Без референсу — секція просто відсутня (REF-BARBER-04-семантика).
- **Розбивка ціни**: базова (`AgreedPrice`) − знижки = підсумок (`FinalPrice`); 0 грн з причиною `loyalty` для безкоштовного візиту (DSC-ADM-05, LYL-ADM-05).
- **Оплата на місці** (`PAY-ADM-04/07`, PAY-ONS-01…05): блок з депозитом і рештою окремо — «Депозит: сплачено (картка, 14:02) · Решта: до сплати 340 ₴» + кнопка **«Оплата на місці»** (видима, поки є несплачена частина):
  - модальне вікно: форма — **Готівка | Картка POS** (radio), сума показана і не редагується (`FinalPrice` − депозит);
  - підтвердження → `PaymentCaptured` (Payment #2) → статус «Оплачено», рядок «Решта: сплачено (готівка/POS, HH:MM, адмін)»;
  - чек Checkbox на суму решти — статус після створення показується тут же: ⏳ `CREATED` → ✅ `DONE` (посилання на чек) → ⚠️ `CANCELLED/ERROR` з причиною і кнопкою **«Повторити чек»** (позначка оплати не відкочується, PAY-ONS-03);
  - повторний клік не створює другий `Payment`/чек (PAY-ONS-04); факт логується (хто, коли, форма) — PAY-ONS-05;
  - для walk-in у барбера та сама дія в mobile (`barber-screens.md` §1.3); позначка відображається тут у календарі після синхронізації.
- **Дії**: Підтвердити (якщо очікує), Перенести, Скасувати — команди `scheduling` (MNG-ADM-15).
  - **Перенести** → модальне вікно з вибором нового слота (той самий флоу, що `booking-flow.md` екран 3); слот валідується за тими самими правилами.
  - **Скасувати** → confirmation: «Візит буде скасовано, клієнт отримає сповіщення» (+ опційне поле причини). Після скасування слот автоматично пропонується черзі (`WTL-003`).
  - **Позначити no-show** →confirmation: «Візит буде позначено як нез'явку; депозит не повертається» (`NSH-BAR-01`-семантика, NSH-ADM). Авто-фіксація спрацьовує і без цієї кнопки (NSH-001).
  - **Додати до галереї** (після завершення): пара «до/після» → черга модерації (§11, PRT-ADM).
- **Референс/коментар**: адмін може змінити або прибрати (скарга/помилка клієнта) — дія логується (REF-ADM-04); історія змін референсу/коментаря видно в цій же панелі (REF-ADM-03).

## 6. Клієнти (CRM) (`MNG-ADM-16`, LYL-ADM-02/03, DSC-ADM-03)

### 6.1 Список «Клієнти»

- **Layout**: заголовок + пошук (ім'я / телефон) → фільтр-бар (локація, статус лояльності) → таблиця.
- **Колонки**: Ім'я | Телефон | Візитів | Останній візит | Прогрес лояльності (`3/7`) (LYL-ADM-02) | VIP (бейдж, якщо є) | Дії (Відкрити).
- **Порожній стан**: «Клієнтів ще немає». Деактивованих клієнтів не буває (роль `client` не деактивується).

### 6.2 Картка клієнта

- **Профіль**: ім'я, телефон, контакти; **VIP-рівень знижки** — поле з логуванням змін (DSC-ADM-03, DSC-VIP-01).
- **Вподобання**: список `Preference` (довжина, продукт, кава) — показ і редагування (crm).
- **Історія візитів**: таблиця — дата, локація, барбер, послуга, ціна (`AgreedPrice`/`FinalPrice`), статус (MNG-ADM-16).
- **Нотатки**: службові (видно барберу у своїй картці клієнта, **не клієнту**) — список + «Додати нотатку» (textarea, дата/автор) (MNG-ADM-16).
- **Лояльність**: прогрес «X/7» + кнопка «Скоригувати» → модальне вікно з причиною; корекція логується (LYL-ADM-02/03).
- **Відгуки клієнта**: список з фільтром (усі/мої) — дані з `feedback` (FDB-ADM-01).
- **Рефералка**: персональний код, список запрошених і винагород (RFR-ADM-02-семантика на рівні клієнта).
- **Дії**: «Записати» (створення візиту для клієнта — шлях до `booking-flow`), «Додати до черги» (лист очікування з передобраним клієнтом — WTL-ADM-02, фаза 17), «Написати» (чат, фаза 7).
- **Телефонний запис** (`/admin/bookings/phone`, T-4738): форма обирає **послугу** обраної локації перед слотом; тривалість візиту — це тривалість послуги (не фіксовані 30 хв). Без обраної послуги кнопка «Створити візит» неактивна. Список послуг порожній, доки не обрано локацію, і це список саме цієї локації, а не першої в довіднику.

## 7. Знижки (`DSC-ADM-01…06`)

### 7.1 Список «Промокоди»

- **Layout**: заголовок + «Створити промокод» → фільтр-бар (Статус: Всі/Активний/Вимкнений; Тип: %/сума) → таблиця.
- **Колонки**: Код | Тип (%/грн) | Значення | Термін дії | Використань (`n/ліміт`) | Статус (бейдж) | Дії (Редагувати · Вимкнути/Увімкнути).
- **Порожній стан**: «Промокодів ще немає — створіть перший».
- **«Вимкнути»** → confirmation: «Код перестане діяти для нових записів. N уже застосованих кодів не зміняться» (DSC-001).

### 7.2 Форма промокоду (`DSC-ADM-01`)

| Поле | Тип | Валідація |
|------|-----|-----------|
| Код | text, uppercase | обов'язковий, унікальний (серверна перевірка; нечутливий до регістру, пробіли ігноруються) |
| Тип | select (% / фіксована сума) | обов'язковий |
| Значення | number | % — 1–100; грн — > 0 |
| Термін дії | дата «від» / «до» | «до» > «від» |
| Ліміт використань | number (або «без ліміту») | ≥ 0 |
| Застосовність | radio (Усі послуги / Обрані) + multiselect послуг | опційно |
| Активний | toggle | — |

### 7.3 Правила знижок (`DSC-ADM-02`)

- **Список**: колонки — Умова (наприклад, «Перший візит», «Непікові: Пн–Чт 10:00–13:00») | Значення | Активне (toggle) | Дії (Редагувати · Вимкнути/Увімкнути).
- **Форма**: Умова (select: перший візит / непікові години); для непікових — дні (checkbox Пн…Нд) + години (від/до); Значення (%/грн); Активне.
- **Валідація**: попередження при дублікаті умови («Така умова вже існує»); години «від» < «до».
- Зміна правила не впливає на вже створені візити (DSC-001) — confirm-banner: «Зміна застосується лише до нових записів».

### 7.4 VIP на картці клієнта (`DSC-ADM-03`)

- Поле «VIP-знижка» (%/грн) на картці клієнта — див. §6.2; зміна логується (хто, коли, причина).
- Примітка-нагадування: VIP комбінується лише з промокодом, сумарний кап 30% (DSC-003).

### 7.5 Статистика знижок (`DSC-ADM-04, DSC-ADM-06`)

- **Layout**: фільтри (Локація, Період, Тип знижки) → картки-підсумки (сумарна знижка, кількість застосувань, середня знижка) → таблиці:
  - **по промокодах**: код, використань, сумарна знижка;
  - **по правилах**: умова, кількість застосувань;
  - **по локаціях**: сумарна знижка за період.
- **Джерело даних**: `AppliedDiscounts` на візитах (не поточні налаштування) — статистика не змінюється при зміні правил (DSC-001).
- **Кап сумарної знижки** (за замовчуванням 30%): поле налаштування тут же або в «Налаштування» (DSC-ADM-06).

## 8. Дашборд KPI («Аналітика») (`ANL-ADM-01…06`)

- **Layout**: фільтр-бар (Період: день/тиждень/місяць/кастом; Локація; Барбер) → ряд карток KPI (9) → графіки.
- **Картки KPI**: Виручка за день · Завантаженість крісла · Середній чек · No-show rate · Скасування · Конверсія запису · Повторний запис · Виручка на годину крісла · Злив через знижки; кожна — значення, ▲/▼ до попереднього періоду, tooltip з формулою (ANL-ADM-02, ANL-008…010).
- **Графіки**: виручка по днях; no-show, скасування, конверсія і повторний запис по барберах (ANL-ADM-03); злив по типах знижок і по промокодах (ANL-ADM-04).
- **Оновлення**: автоматичне з подій; «вчора» — повний звіт, «сьогодні» — поточний стан (ANL-ADM-05).
- **Порожній стан**: «Даних ще немає — після перших візитів». Експорт CSV/Excel — опційно (ANL-ADM-06).
- **Доступ**: лише `admin`; барбер не бачить фінанси мережі (architecture.md).
- **Утримання (фази 16–18)**: no-show rate з розрізом по каналу запису (NSH-005); конверсія waitlist-пропозицій (WTL-ADM-04); ROI кампаній — відправлено/використань/виручка з кодом (WNB-ADM-04, зв'язка з ANL-006).
- **Сертифікати (фаза 20)**: зобов'язання — сума непогашених залишків; breakage — прострочені (GFT-ADM-05).
- **Зростання (фаза 21)**: воронка referral vs органіка (кліки → реєстрації → завершені візити), CAC/LTV referral-клієнтів (RFR-ADM-04).
- **Налаштування no-show** (NSH-ADM-01): хвилини авто-фіксації (15), вікно порогу (90 днів), кількість no-show для обмеження (2), перемикач «повна передоплата після порогу».

## 9. Лист очікування (`WTL-ADM-01…04`)

### 9.1 Список черг

- **Колонки заявки**: Клієнт | Дата заявки | Вікно дат | Точність («на час»/«впораюсь») | Статус (активна / на паузі / є пропозиція).
- **Дії** (`WTL-ADM-02`): Додати клієнта (з картки, розділ 6) · Видалити · Пауза/Зняти паузу · **«Дати слот зараз»** — вручну запустити hold→push→confirm флоу для першого в черзі.
- **Налаштування** (`WTL-ADM-03`): вікно підтвердження (15 хв), довжина soft-hold (15 хв), поріг паузи (3), авто-зняття паузи (7 днів).
- Механіка — ADR 0012; клієнтський бік — `booking-flow.md` (екран 3).

## 10. Кампанії (`WNB-ADM-01…04`)

### 10.2 Форма кампанії (`WNB-ADM-02`)

### 10.3 Картка кампанії (`WNB-ADM-03/04`)

## 11. Галерея (`PRT-ADM-01…04`)

### 11.1 Черга модерації та список

- **Статуси елемента**: `pending_consent` → `pending_review` → `published` / `hidden` (PRT-006).

### 11.2 Модерація елемента (`PRT-ADM-02`)

- Прев'ю пари «до/після»; джерело (візит → картка візиту, клієнт, AI-варіант або фото відгуку); згода клієнта (коли, який варіант анонімності).

- Відкликання згоди клієнтом ховає елемент **миттєво** без дії адміна (PRT-006); це видно в списку як статус.

## 14. Оплати (`PAY-ADM-01…09`)

### 14.1 Список «Оплати»

- **Фільтр-бар**: локація, період, статус (очікує депозиту / депозит сплачений / очікує решти / оплачено / refund у процесі / refund failed), тип (депозит / решта / refund).
- **Колонки**: Візит | Клієнт | Сума | Форма (картка/POS/готівка) | Статус | Чек (іконка → відкрити/скачати, PAY-ADM-03) | Час.
- Refund-и видно в тому ж списку з причиною та ініціатором (PAY-ADM-08); `refund_failed` — з причиною і кнопкою «Повторити refund» (PAY-009).

### 14.2 Політика депозита (`PAY-ADM-09`)

| Поле | Тип | Валідація/дефолт |
|------|-----|------------------|
| Депозит | % від `FinalPrice` | 0–100; дефолт **30**; 0 = вимкнено |
| Округлення депозита | select (1/5/10 грн) | дефолт 10 |
| Вікно скасування | number, годин | 0–72; дефолт **4** |

- **Екран**: `/settings/deposit-policy` у `apps/admin` (вкладка «Політика депозиту»): відсоток (0–100, ціле; 0 = вимкнено), округлення (select 1/5/10 грн), вікно скасування (0–72 год). Дані — `AppSetting` (ключ `billing.depositPolicy`), API — `GET/PUT /admin/settings/deposit-policy`; PUT приймає часткові зміни й тихо відкидає невалідне поле, не переписуючи чинну політику.
- **Версії (T-4444)**: кожна зміна правил інкрементує версію й пише незмінний рядок у `DepositPolicyVersion` (%, округлення, вікно, хто, коли) в тій самій транзакції; незмінена політика версію не рухає. `GET /admin/settings/deposit-policy` віддає `version`, `GET /admin/settings/deposit-policy/history` — затверджені набори; екран показує «Версія N» і список історії. Записи клієнтів зі снепшотом старої версії не переоцінюються.
- **Споживання**: `BookAppointment` читає політику раз на запис і снепшотить її на `Booking` (`depositAmount/Percent/Rounding/cancellationWindowHours`); без збереженого налаштування діють дефолти PAY-ADM-09 (30% / 10 / 4 год). Кабінет рахує дедлайн від початку візиту, тож перенесення зсуває його (T-4737).
- **Скоуп**: єдина політика на мережу в v1; override по локації — з фази 9 (поле з'явиться на сторінці локації); по барберу — відхилено (PAY-ADM-09).
- **Зміна** → постійний info-банер «Застосується лише до нових записів» + тост після збереження — % і вікно снепшотяться на `Appointment` при записі; скасування оцінюється за снепшотом свого запису. Невалідні значення блокують кнопку «Зберегти» з поясненням під формою.
- Поруч — посилання на текст політики клієнта (що саме бачить клієнт на екрані депозиту, PAY-WEB-07).

**Загальні правила (усі ролі):**

- **UI приховує, API перевіряє**: матриця — це не тільки видимість екранів; кожна команда (`scheduling`, `billing`, `crm`, …) на сервері перевіряє роль **і** локаційний скоуп (`StaffAssignment`/призначення менеджера). Приховування в UI — захистом не є.
- **Деструктивні і грошові дії** — confirmation + лог (хто, коли): вимкнення локації/барбера, зняття no-show з refund (PAY-005б), повтор refund (`PAY-009`), анулювання винагороди (RFR-ADM-02), скасування сертифіката (GFT-ADM-04), корекція лояльності (LYL-ADM-03).
- **Тільки `admin`** (не делегується): мережеві ціни і послуги, політика депозита (крім override фази 9), промокоди/правила, кампанії, налаштування інтеграцій, персонал, зняття no-show з refund, повтор refund.
- «—» = пункту меню немає; прямий URL — 403. Екрани з локаційним скоупом фільтруються за призначенням, як календар за `StaffAssignment`.

## 17. Блог — CMS статей (`MNG-ADM-17`, реалізовано 2026-09-28, T-031)

- **Екран** `/blog` у `apps/admin`: список статей (чернетки й опубліковані) + форма нової статті; кожна стаття — картка з редагуванням і дією публікації.
- **Поля статті** (`Article`, контекст `content`): заголовок, URL (slug, унікальний), анонс, текст, обкладинка, автор, теги; статус `draft` / `published` і дата публікації.
- **Дії**: «Зберегти чернетку», «Зберегти зміни», «Опублікувати», «Зняти з публікації» (не видалення — знята стаття лишається в CMS чернеткою). Зняття миттєво прибирає її із сайту.
- **Стани** (admin/16-shared, T-4513): помилка запиту — `AlertBanner` + «Спробувати ще раз», порожній список — «Статей ще немає» із підказкою, що стаття з'явиться на сайті лише після публікації; дубль URL (409) і неповна стаття (400) — підказка в банері, введений текст не зникає.
- **Публікація миттєва**: опублікована стаття вже в публічному API (`GET /content/articles`) і на сайті `/blog` (`MNG-ADM-17`); сайт кешує стрічку ISR 5 хв, тож поява в Google — протягом хвилин.
- **Мова команд домену**: draft → publish → unpublish (не `setStatus`); кожна дія пише подію `content.article.*` у transactional outbox.
