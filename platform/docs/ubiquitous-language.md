# Ubiquitous language

Слова нижче — для коду, адмінки, ТЗ і розмов про софт. Не змішувати з маркетинговим тоном бренду (`brand/voice-tone.md`).

## Мережа

| Термін | Значить | Не значить |
|--------|---------|------------|
| Location | Точка мережі з кодом `CLT-01` | URL, папка на диску |
| Chair | Фізичне крісло в локації | Барбер, слот |
| StaffAssignment | Барбер працює на цій точці | Трудовий договір |
| Network | Усі наші точки | Франшиза третіх осіб |
| OpeningHours | Години роботи локації (по днях тижня) | Розклад окремого барбера (це Availability) |

## Люди

| Термін | Контекст | Значить |
|--------|----------|---------|
| User | identity | Хто може увійти |
| PhoneNumber | identity | Логін клієнта (`+380…`), унікальний. Заміна номера — OTP на новий, той самий `User` (T-4620) |
| OtpChallenge | identity | SMS-код для входу; не пароль |
| Session | identity | Вхід на `web` / `mobile` / `admin` |
| Role | identity | `client` \| `barber` \| `admin` |
| Client / ClientProfile | crm | Гість, якого стрижуть |
| Barber | locations + identity | Майстер з роллю `barber` |
| Admin | identity | Засновник |

«Клієнт» у коді CRM ≠ «клієнт HTTP». HTTP: `caller`, `actor`.

Клієнт не має `password`. Вхід = `RequestOtp` + `VerifyOtp`. Сайт і додаток — той самий `User`.

`Admin` входить за `username` + `password` (T-013): тільки роль `admin` створює admin-сесію. `username` та `passwordHash` (scrypt) — на `User`, клієнти їх не мають.

## Запис

| Термін | Значить |
|--------|---------|
| Appointment | Заброньований візит **однієї** людини |
| AppointmentParty | Пакет на двох (`father-son`): одна ціна, дві `PartyLeg` (ADR 0011) |
| PartyLeg | Нога партії: батько або син; барбер, крісло, тривалість |
| FulfillmentMode | `sequential` (черга, 90 хв) \| `parallel` (два крісла, 50 хв) |
| CompanionName | Ім’я дитини на нозі сина; без `User` у v1 |
| TimeSlot | Проміжок, який можна зайняти |
| Availability | Правило, коли барбер приймає |
| UnavailableDay | Інтервал, коли барбер не приймає. Уже створені візити стають конфліктами і самі не скасовуються |
| BookAgain | Намір нового запису з завершеного візиту: та сама локація, послуга і барбер, новий слот і нова ціна |
| Book / Confirm / Reschedule / Cancel / Complete | Команди життєвого циклу |
| HaircutReference | Зображення бажаної зачіски, прикріплене до Appointment або PartyLeg (ID із `haircut-ai` або зовнішній upload); опціональне |
| AppointmentComment | Текстовий коментар клієнта до візиту (≤ 500 символів); опціональний |
| AgreedPrice | Ціна візиту або партії, зафіксована при записі (снепшот з `catalog`); зміна ціни не впливає на візит (ADR 0006, для пакета — на `AppointmentParty`, ADR 0011) |
| AgreedDuration | Тривалість візиту або партії, зафіксована при записі. `end` рахується від неї. Зміна тривалості в каталозі не рухає вже створені візити (T-4618) |
| WalkIn | Візит, створений персоналом на місці (без OTP, без депозиту); джерело `walk-in` на `Appointment` або `AppointmentParty` |

Не використовувати `Order`, `BookingEntity`, `Event` для візиту. `Event` — лише доменна подія. Не називати партію `Order` або двома незв’язаними `Appointment`.

## Контент

| Термін | Значить |
|--------|---------|
| Article | Стаття блогу; одна для сайту і додатка |
| ArticleBlock | Фрагмент тіла після парсера: абзац, заголовок, список, цитата, зображення. Клієнти рендерять блоки, не HTML |
| CanonicalUrl | URL на `apps/web` (`/blog/{slug}`), не deep-link додатка |
| Draft / Published | Стани статті. Відкладений вихід — це чернетка з `publishAt`, не третій статус |
| Author | Ім'я і роль на статті. Окремого агрегату автора немає |
| Slug | Унікальний URL статті (`/blog/{slug}`). Після публікації зміна пише `SlugRedirect` на поточний slug |
| SlugRedirect | Старий slug опублікованої статті. Не віддається новій статті. Сайт відповідає 301 |
| Excerpt | Анонс картки стрічки. Вкладка браузера може взяти його, якщо `SeoDescription` порожній |
| SeoTitle / SeoDescription | Заголовок і опис для пошуку. Порожні — значить title / excerpt |
| Featured | Єдина опублікована стаття, яку стрічка показує першою |
| Tag | Єдина мітка статті. Архів і пошук фільтрують масив рядків; таблиці тегів немає; категорій немає |
| DraftArticle / PublishArticle / UnpublishArticle | Команди мовою домену; `setStatus` — заборонений синонім |
| ArticlePublished | Подія outbox: стаття з'явилась на сайті; підписки мають бути ідемпотентними (ADR 0009) |

## Утримання і галерея

| Термін | Значить |
|--------|---------|
| WaitlistEntry | Заявка в листі очікування: конфігурація (локація + послуга + барбер/«Будь-який») + вікно дат + точність часу (ADR 0012) |
| SlotHold | Утримання звільненого слота на 15 хв під час пропозиції черзі; не бронь, конвертується лише явним підтвердженням (ADR 0012) |
| SlotOffer | Пропозиція звільненого слота першому в черзі з вікном підтвердження |
| NoShow | Нез'явка без скасування; фіксується автоматично через X хв після слота (NSH-001) |
| WinbackCampaign | Кампанія по сегменту CRM: персональний промокод + push (WNB-*) |
| PortfolioItem | Елемент публічної галереї «до/після»; публікація = згода клієнта + модерація адміна |
| ClientConsent | Згода клієнта на публікацію фото роботи (так / анонімно / ні); відкликання ховає елемент миттєво |
| GiftCertificate | Передплачений сертифікат: номінал, код, баланс, строк дії; форма оплати, не ціна і не знижка (ADR 0013) |
| CertificateBalance | Залишок сертифіката; часткове погашення зберігає залишок |
| Redemption | Списання з балансу сертифіката на оплату візиту (повне або часткове) |
| Breakage | Прострочені невикористані залишки сертифікатів — фактична маржа (GFT-ADM-05) |
| InviteCode | Персональний реферальний код клієнта; джерело посилання «приведи друга» (ADR 0014) |
| ReferredBy | Посилання на запрошувача на профілі друга; фіксується при першій реєстрації, імутабельне |
| ReferralDiscount | Знижка рефералу (перший візит) і винагорода запрошувачу (після завершення візиту друга) |
| DayOff | Одноразовий вихідний/діапазон барбера (відпустка, лікарняний) поверх тижневого шаблону графіка |
| AvailabilityChanged | Подія зміни графіка барбера з джерелом (barber self-service / admin) — аудит (SCH-008) |
| PublicAvailability | Read-only проекція вільних вікон для гостя (7 днів); не бронює — клік веде у флоу з повторною валідацією (LST-001) |
| GbpReviewUrl | Посилання на сторінку відгуків GBP локації; друга (публічна) кнопка вибору каналу відгуку (GBP-003) |
| ReviewGating | Заборонена практика фільтрації хто отримує запрошення на публічний відгук; у платформі виключена конструктивно (GBP-004) |
| PublicationLifecycle | Стани публічності відгуку: `private → pending_review → published / rejected`; редагування опублікованого повертає в модерацію (PUB-002) |
| ServicePage | Канонічна SEO-сторінка послуги `/services/{slug}` (Schema.org Service/FAQPage); варіанти по локаціях — з мережею (фаза 9+, SRV-002) |

## Заборонені синоніми в коді

- `Shop` / `Branch` / `Salon` → `Location`
- `Master` / `Employee` → `Barber` (роль) або `StaffAssignment`
- `Ticket` / `Order` → `Appointment`
- `ChatRoom` → `Conversation`
- `Post` → `Article`
- `Customer` у identity → `User`; у CRM → `ClientProfile`
- `password` / `magic link` для клієнта → `OtpChallenge`
