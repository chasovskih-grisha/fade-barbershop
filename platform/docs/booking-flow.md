# Флоу запису (booking flow) — web і mobile

> Специфікація **екранів** клієнтського флоу запису: **послуга → [режим, якщо пакет] → барбер → слот → зачіска і коментар → підтвердження і оплата**. Один флоу на web і mobile (той самий `scheduling`), відмінності mobile — наприкінці. Кожен екран: Layout, Компоненти, Стани, Критерії.
>
> Критерії: `acceptance-criteria/03-appointment-haircut-reference.md` (REF), `02-ai-haircut-suggestion.md` (AI), `07-discounts.md` (DSC), `01-billing-payments.md` (PAY), `05-loyalty-free-visit.md` (LYL), `10-father-son-party.md` (PARTY). Дані кроків 1–3 керуються в адмінці: `admin-screens.md`, `web-screens.md`.

**Wireframes** — каркас для імплементації: фіксують **регіони, компоненти і стани**, не пікселі (кольори/типографіка — `references/design-direction.md`, брендбук). Маркери: `[•]` дія/CTA · `⦿/○` вибір · `[S]` sticky-зона · `⚑` попередження · `⏳` loading-скелетон · `∅` порожній стан · `↔` порівняння.

## Екран 0 — Локація

- **Layout**: на `https://fade.com.ua/booking` — картки всіх активних локацій (як на `/locations`); за наявності обраної — перевизначення з шапки. **Mobile**: екран вибору локації в групі `(client)`.
- **Deep link**: `https://fade.com.ua/booking/{location-code}` серверно валідує код, підставляє локацію, пропускає екран 0 і відкриває послуги саме цієї локації; невідомий/вимкнений код не підміняється іншою локацією. Англійська локаль — `/en/booking/{location-code}`.
- **Компоненти**: картка локації (назва, адреса, години, CTA «Обрати»); на `/booking` картка має href на `/booking/{location-code}`; бейдж «2 крісла».
- **Стани**: loading — скелетони; empty — «Локацій ще немає».
- **Правило**: вимкнена локація недоступна для запису (`MNG-ADM-02`); послуги і ціни показуються по локації (`MNG-ADM-11/12`).

Wireframe — вибір локації (mobile; web — та сама сітка карток у 2 колонки під шапкою):

```
┌──────────────────────────────┐
│ Крок 0/5 · Оберіть локацію   │
│ ┌──────────────────────────┐ │
│ │ Сіті Лейк                │ │
│ │ вул. … · 2 крісла        │ │
│ │ Сьогодні 09:00–20:00     │ │
│ │ Відкрито зараз  [Обрати] │ │
│ └──────────────────────────┘ │
│ ⏳ скелетони карток (loading)│
│ ∅ «Локацій ще немає»         │
└──────────────────────────────┘
```

- Картка = назва / адреса / години на сьогодні / бейдж «2 крісла» / CTA «Обрати» (`MNG-ADM-02`, `MNG-ADM-03`).
- Вимкнена локація — без картки (не disabled); обрана локація перевизначає контекст шапки сайту.

## Екран 1 — Послуга

- **Layout web**: header (крок «1/5», прогрес) → чипси категорій (стрижка, гоління, борода, догляд) → сітка карток послуг → футер з «Далі» (disabled до вибору). **Mobile**: список карток з тими ж полями.
- **Компоненти картки**: назва, тривалість (хв; для `father-son` — «50 або 90 хв»), ціна в обраній локації, радіо-вибір; недоступна послуга — без картки (не disabled).
- **Стани**: loading — скелетони; empty — «У цій локації послуг поки немає»; вибір — підсвічена картка.
- **Валідація**: без вибору «Далі» неактивне; показуються лише активні послуги, доступні в локації (`MNG-ADM-10`, `MNG-ADM-12`).
- **Далі для `father-son`**: не на екран барбера, а на **екран 1б** (режим). Інші SKU — одразу на екран 2.

Wireframe — послуга (mobile; web: чипси + сітка карток, футер той самий):

```
┌──────────────────────────────┐
│ ← Крок 1/5 · Послуга         │
│ (усі)(стрижка)(гоління)(бор) │  чипси категорій
│ ┌──────────────────────────┐ │
│ │ ⦿ Чоловіча стрижка       │ │
│ │   50 хв · 600 ₴          │ │
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ ○ Батько + син           │ │
│ │   50 або 90 хв · 900 ₴   │ │
│ └──────────────────────────┘ │
│ ⏳ скелетони                  │
│ [S] [Далі →]   ← disabled    │
└──────────────────────────────┘
```

- Категорія фільтрує сітку; ціна завжди в обраній локації (`MNG-ADM-11/12`); недоступна послуга — без картки (`MNG-ADM-10`).
- `father-son` — звичайна картка; «Далі» веде на екран 1б, не на барбера.
- Без вибору футер disabled; вибір — підсвічена картка (mobile: tap, не радіо).
- **Обрана картка** (T-4742): той самий обраний стан, що в обраного слота (екран 3) — заливка `accent`, текст `accent-fg`, `aria-pressed` істинне лише на ній. Невибрані картки лишаються в звичайному стані; кільце `ring-fg` на обраній не лишається.

## Варіанти тривалості (T-4419)

- Послуга каталогу може мати варіанти тривалості: коротший, стандартний і довший, кожен зі своєю
  тривалістю й поправкою до ціни локації (`priceDelta`). Послуга без варіантів — стандартна
  тривалість, як раніше.
- Екран 1 показує варіанти під послугою; обраний варіант їде далі як `variantLabel`.
- Екран 3 будує сітку слотів від тривалості обраного варіанта: для варіанта 30 хв останній старт
  пізніший, ніж для 60 хв, на ту саму різницю.
- Запис снепшотить вибір: `durationVariant`, `agreedDuration` варіанта й `agreedPrice` = ціна
  локації + `priceDelta`. Пізніша зміна каталогу ці снепшоти не рухає.
- Невідомий `variantLabel` — **400**, а не мовчазний відкат до базової тривалості; без
  `variantLabel` поведінка незмінна.

## Екран 1б — Режим «Батько + син» (`PARTY-*`)

Показується **лише** якщо на екрані 1 обрано `father-son`. Інакше кроку немає (прогрес лишається 1/5… зсув нумерації для клієнта не показуємо окремим «6 кроків» — це відгалуження кроку 1).

- **Layout**: header → дві великі картки режиму → футер «Далі» (disabled до вибору).
- **Картка sequential**: заголовок «По черзі», підзаголовок «Один барбер · 90 хв», текст: спочатку син, потім батько; друге крісло лишається для інших.
- **Картка parallel**: заголовок «Одразу», підзаголовок «Два крісла · ~50 хв», текст: обидва стрижуться разом. На точці з 2 кріслами — попередження «займете весь зал» (`PARTY-006`). Якщо зараз неможливо (один майстер у зміні) — картка disabled, причина на картці (`PARTY-005`).
- **Ціна**: одна й та сама на обох картках (пакет локації).
- **Стани**: обидва доступні; лише sequential; loading слотів режиму не потрібен — доступність parallel можна перевірити грубо по кількості активних барберів локації, точний слот — на екрані 3.
- **Валідація**: без режиму «Далі» неактивне (`PARTY-002`).

Wireframe — режим (лише для father-son; інші SKU цей крок минають):

```
┌──────────────────────────────┐
│ Крок 1б · Режим виконання    │
│ ┌──────────────────────────┐ │
│ │ ⦿ По черзі               │ │
│ │   Один барбер · 90 хв    │ │
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ ○ Одразу          ⚑      │ │
│ │   Два крісла · ~50 хв    │ │
│ └──────────────────────────┘ │
│ [S] [Далі →]                 │
└──────────────────────────────┘
```

- Ціна однакова на обох картках (пакет локації); ⚑ «займете весь зал» на 2-крісельній точці (`PARTY-006`).
- Parallel disabled з причиною на картці, якщо зараз неможливо (`PARTY-005`); без вибору «Далі» disabled (`PARTY-002`).

## Екран 2 — Барбер

- **Layout**: список карток барберів локації + першою опцією **«Будь-який барбер»** (перший вільний слот); футер «Далі».
- **Parallel (`father-son`)**: перша опція **«Будь-які два вільні»**; далі — мультивибір **рівно двох різних** барберів. Один і той самий двічі — невалідно (`PARTY-004`).
- **Компоненти картки**: фото (опційно), ім'я, чип локації; опційно — 2–3 найближчі вільні слоти (скорочує шлях до екрана 3). Рейтинг барбера — **не показується** до публічних відгуків (фаза 25, `PUB-WEB-02`; у флоу — опційно після ввімкнення, з порогом PUB-006).
- **Стани**: empty — «У цій локації барберів ще немає». Parallel + менше двох активних барберів — не повинні сюди потрапити (режим уже disabled на 1б).
- **Правила**: деактивовані барбери приховані (`MNG-ADM-05`); барбери інших локацій недоступні (`MNG-ADM-06`).

Wireframe — барбер:

```
┌──────────────────────────────┐
│ ← Крок 2/5 · Барбер          │
│ ┌──────────────────────────┐ │
│ │ ○ Будь-який барбер       │ │
│ │   перший вільний слот    │ │
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ ○ [фото] Олексій         │ │
│ │   найближчі: 12:00 14:30 │ │
│ └──────────────────────────┘ │
│ [S] [Далі →]                 │
└──────────────────────────────┘
```

- Parallel: перша опція «Будь-які два вільні», далі мультивибір рівно двох різних (`PARTY-004`).
- **Обрана картка** (T-4742): та сама заливка `accent` і текст `accent-fg`, що в обраного слота (екран 3); `aria-pressed` істинне лише на обраних картках (для parallel — на кожній із двох), невибрані лишаються в звичайному стані без кільця.
- 2–3 найближчі слоти на картці — скорочення шляху до екрана 3; рейтинг — не до фази 25 (`PUB-WEB-02`).
- Деактивовані барбери і барбери чужих локацій — відсутні (`MNG-ADM-05/06`).

## Екран 3 — Слот

- **Layout**: стрічка дат (горизонт 14 днів, за рішенням) → сітка слотів (крок 15 хв, враховує тривалість послуги); футер «Далі».
- **Компоненти**: дата (активна/вихідний — від `OpeningHours`); слот (вільний / зайнятий-disabled / обраний-підсвічений).
- **Стани**: loading — скелетони сітки; empty — «На цю дату слотів немає» + підказка змінити дату/барбера + картка **waitlist** «Повідомити, якщо звільниться» (`WTL-WEB-01`: конфігурація підставлена з кроків 1–2, вікно дат, точність часу; механіка — ADR 0012, фаза 17).
- **Валідація слота** (вільний = усі умови разом): `Availability` барбера (`MNG-ADM-07`), `OpeningHours` локації (`MNG-ADM-03/09`), інваріант 2 крісел (фаза 4). Для `father-son`: sequential — 90 хв на одному кріслі; parallel — спільний старт, два крісла, ноги 45 і 50 хв (`PARTY-003…005`, `PARTY-011`).

Wireframe — слот:

```
┌──────────────────────────────┐
│ ← Крок 3/5 · Слот            │
│ [12пн][13вт][•14ср][15чт] →  │ стрічка дат (горизонт 14 днів)
│ 09:00  09:15  09:30  09:45   │
│  [•]    [ ]    [x]    [ ]    │ сітка, крок 15 хв
│ 10:00 ── зайнято ── 10:45    │
│ [S] [Далі →]                 │
└──────────────────────────────┘
```

Empty-стан (слотів немає):

```
┌──────────────────────────────┐
│ ∅ «На цю дату слотів немає»  │
│ підказка: змінити дату/барб. │
│ ┌──────────────────────────┐ │
│ │ Повідомити, якщо         │ │
│ │ звільниться [Підписатися]│ │ waitlist (WTL-WEB-01)
│ └──────────────────────────┘ │
└──────────────────────────────┘
```

- Вихідний день — disabled за `OpeningHours`; «вільний» = `Availability` + `OpeningHours` + інваріант 2 крісел − тривалість послуги.
- father-son: sequential — 90 хв на одному кріслі; parallel — спільний старт, два крісла (`PARTY-003…005`, `PARTY-011`).
- Waitlist: конфігурація підставлена з кроків 1–2; механіка — ADR 0012 (фаза 17).

## Екран 4 — Зачіска і коментар (REF-WEB-01…03/05, REF-MOB-01)

Для соло-візиту — як нижче, одна секція. Для `father-son` — **дві секції** (батько / син): у сина обов’язкове ім’я (`CompanionName`, `PARTY-009`, `PARTY-WEB-04`); референс і коментар опційні на кожну ногу.

- **Layout**: секція «Референс» (radio-джерела + прев'ю) → секція AI (inline) → секція «Коментар» (textarea + лічильник) → футер «Далі».
- **Компоненти референсу — три джерела (radio + прев'ю):**
  1. **«З AI-підбору»** — сітка мініатюр вибраних клієнтом варіантів із попередніх генерацій.
  2. **«Завантажити фото»** — власний референс; фото обов'язкове (REF-WEB-05).
  3. **«Без референсу»** — за замовчуванням, без фото.
- **AI inline** (коли обрано джерело 1 і варіантів немає / потрібен новий):
  - **Upload**: dropzone/кнопка, jpg/png/webp ≤ 10 МБ, мін. роздільність ~800×800 (AI-WEB-01); mobile — галерея або камера (AI-MOB-02).
  - **Consent**: перед першою генерацією — модальне вікно згоди (текст укр., «Погоджуюсь» / «Скасувати») (AI-WEB-02).
  - **Processing**: статус «Завантажено → Обробка AI → Готово/Помилка» + орієнтовний час (AI-WEB-03); сторінку можна покинути — результат з'явиться в історії.
  - **Gallery**: 3–4 варіанти на фото клієнта (AI-WEB-04); збільшення, «Цей варіант», «Згенерувати ще раз» — ліміт 3 генерації на добу (AI-ADM-03).
  - **Error**: невалідне фото — зрозуміла помилка (укр.) з підказкою; спроба не витрачає ліміт (AI-WEB-06).
- **Коментар**: textarea ≤ **500 символів** з лічильником; звичайний текст без HTML (REF-WEB-02); плейсхолдер: «зняти на 2 мм, чубчик залишити».

Wireframe — зачіска і коментар:

```
┌──────────────────────────────┐
│ ← Крок 4/5 · Зачіска         │
│ РЕФЕРЕНС                     │
│ (•) З AI-підбору             │
│ ( ) Завантажити фото         │
│ ( ) Без референсу            │
│ ┌────┐┌────┐┌────┐           │
│ │ v1 ││ v2 ││ v3 │ мініатюри │
│ └────┘└────┘└────┘           │
│ [+ Завантажити фото]         │ AI inline
│ Згода AI → Обробка ⏳ → Готово│
│ КОМЕНТАР (0/500)             │
│ [________________________]   │
│ [S] [Далі →]                 │
└──────────────────────────────┘
```

- Три джерела (radio) — REF-WEB-01; «Без референсу» — дефолт; фото обов'язкове лише для «Завантажити фото» (REF-WEB-05).
- AI inline: згода перед першою генерацією (AI-WEB-02), статус обробки (AI-WEB-03), 3–4 варіанти, «ще раз» — ліміт 3/добу (AI-WEB-05, AI-ADM-03), помилка без втрати ліміту (AI-WEB-06); mobile — камера/галерея (AI-MOB-02).
- Коментар ≤ 500, plain text, лічильник (REF-WEB-02); для party — дві секції з іменем сина (`PARTY-WEB-04`).

## Екран 5 — Підтвердження і оплата

- **Layout web**: дві колонки — ліва «Підсумок» (деталі візиту + референс + коментар), права «Оплата» (промокод, розбивка, платіж). **Mobile**: вертикальний стек у тому ж порядку; футер «Підтвердити».
- **Компоненти підсумку (REF-WEB-03)**: послуга, барбер, час, локація; **референс — мініатюра, клік — повний розмір**; коментар; кнопка «Назад» — змінити будь-що до підтвердження. Для `father-son`: режим, хто стриже батька/сина, час **закінчення** партії, ім’я сина (`PARTY-WEB-05`).
- **Промокод (DSC-WEB-01…03, DSC-MOB-01)**: поле + миттєва валідація (успіх — знижка в розбивці; помилки — «Код не дійсний» / «Термін дії закінчився» / «Ліміт використань вичерпано», не блокує запис); нечутливий до регістру, пробіли ігноруються.
### Крок підтвердження до FinalPrice (T-4736)

Поки `FinalPrice` не існує (знижки й депозит — T-090/T-091), екран підтвердження показує обраний візит і каталожну ціну, без панелі оплати:

- Факти зі стану флоу: **локація, послуга (назва й тривалість), майстер, обраний слот**; коментар лишається під ними.
- **Ціна** — каталожна ціна вибраної послуги в грн без копійок (`N ₴`), та сама, що на картці послуги. Це не `FinalPrice` і не сума зі знижками.
- Під фактами один рядок — **«Оплата на місці»**. Депозит, промокод і платіжна кнопка не малюються (зокрема не як нулі).
- Кнопка лишається «Підтвердити запис».

Коли T-090 прийде, каталожний рядок стане базовим рядком розбивки на цьому ж екрані — другої ціни не буде.

### Розбивка ціни (FinalPrice) — компонент

- **Місце**: Екран 5 — у панелі «Оплата» (web: права колонка; mobile: блок над sticky-футером); той самий компонент на екрані оплати депозиту (гілка 2). Показується **до підтвердження** (DSC-006).
- **Рядки** (виводяться лише за наявності):
  1. **Базова ціна** — `AgreedPrice` (снепшот повної ціни по локації, ADR 0006); завжди видно.
  2. **Знижки — кожна окремо**: «VIP −10%» / «Промокод INSTAGRAM10 −20%» / «Перший візит −10%» — тип + сума; стек лише VIP+промокод, кап 30% (DSC-003). При обрізанні капом додається рядок «Сумарна знижка обмежена 30%».
  3. **Підсумок** — `FinalPrice`, жирний, ≥ 0 грн (DSC-004).
  4. **Депозит і решта** (депозит увімкнено, v1): «Депозит (30%): N ₴ — сплатити зараз», «Решта: M ₴ — на місці після послуги» (PAY-WEB-02).
  5. **Безкоштовний 7-й візит**: рядок «Знижка 100% (7-й візит безкоштовно)», підсумок «0 ₴», оплата не пропонується (LYL-WEB-02, LYL-MOB-03).
- **Формат сум**: грн без копійок, знижки зі знаком «−», підсумок із «₴».
- **Стани**: без знижок — рядки 1→3 (суми однакові); промокод — інлайн-валідація (успіх — рядок з'являється одразу; помилки «Код не дійсний» / «Термін дії закінчився» / «Ліміт використань вичерпано» — рядка немає, DSC-WEB-01…03); завантаження підтвердження — скелетони розбивки.
- **Mobile**: той самий компонент вертикально; `FinalPrice` закріплений у sticky-футері над кнопкою «Підтвердити», щоб сума завжди була видна.
- **Критерії**: DSC-006, DSC-004, DSC-003, PAY-WEB-02, PAY-002 (чек = фактично сплачена сума), LYL-WEB-02/LYL-MOB-03.
- **Оплата — три гілки:**
  1. **Безкоштовний 7-й візит** — бейдж «Цей візит безкоштовний», панель оплати не показується (LYL-WEB-02, LYL-MOB-03).
  2. **Депозит при записі** (рішення, PAY-WEB-02) — платіж карткою на **30% `FinalPrice`** (налаштовується); без успіху запис у статусі «Очікує депозиту», не «Підтверджено»; подвійний клік не створює другу оплату (PAY-WEB-03); політика скасувань показана (PAY-WEB-07).
  3. **Решта на місці** — після послуги: картка через POS або готівка; оплата/повторна спроба — з картки візиту (PAY-WEB-01).
- **Стани**: submitting (кнопка завантаження, блокування), success (екран підтвердження: деталі, статус оплати, посилання на чек — PAY-WEB-04), error оплати (банер + повторна спроба; статус не втрачається — PAY-WEB-06).

Wireframe — підтвердження і оплата (web: 2 колонки; mobile: вертикальний стек у тому ж порядку):

```
┌───────────────────┬─────────────────────┐
│ ПІДСУМОК          │ ОПЛАТА              │
│ Стрижка · Олексій │ [Промокод ________] │
│ 14:30 · Сіті Лейк │ Базова ціна  600 ₴  │
│ [референс ↔]      │ Промокод     −120 ₴ │
│ Коментар: «…»     │ ПІДСУМОК     480 ₴  │
│ [← Змінити все]   │ Депозит 30%  140 ₴  │
│                   │ Решта на місці 340 ₴│
│                   │ [Сплатити депозит]  │
└───────────────────┴─────────────────────┘
```

- Розбивка — компонент «FinalPrice» (рядки: базова → знижки по одній → підсумок → депозит/решта; DSC-006, PAY-WEB-02); mobile: `FinalPrice` у sticky-футері над «Підтвердити».
- Гілки оплати: (1) безкоштовний 7-й — бейдж «Цей візит безкоштовний», панелі немає (LYL-WEB-02/LYL-MOB-03); (2) депозит 30% — без успіху статус «Очікує депозиту» (PAY-WEB-02/03); (3) решта на місці після послуги (PAY-WEB-01).
- Стани: submitting — кнопка блокується (PAY-WEB-03); success — екран підтвердження + чек депозиту (PAY-WEB-04); error — банер + повторна спроба (PAY-WEB-05/06); політика скасувань показана на екрані (PAY-WEB-07).

## Після підтвердження (T-4735)

Екран, який клієнт бачить після `POST /booking/bookings` — це підтвердження створеного візиту, не новий крок флоу.

- Завжди показує чотири факти візиту: **локацію, послугу, майстра і обраний час**.
- Референс-фото і коментар показуються, коли візит їх має. Їх відсутність не ховає чотири факти.
- Одне посилання — **«Мої візити»** на `/account/appointments` (плюс «На головну»).
- Не містить чипсів вподобань, рейтингу, перемикача нагадувань і бота підтримки: ці контролі нічого не зберігали.
- Немає кнопки календаря, доки T-4446 не дасть посилання з початком і кінцем візиту.

## Після запису (редагування з кабінету)

- «Мої візити» → картка візиту: **змінити референс і коментар**, поки візит не підтверджений барбером; після — лише перегляд (REF-WEB-04, REF-MOB-02).
- Оплата і повторна спроба — з картки візиту (PAY-WEB-01, PAY-WEB-05).

## Mobile-відмінності (клієнт)

- Кроки — **окремі екрани** з прогрес-баром і back-gesture (Expo Router, група `(client)`); вибір картки — tap, не радіо.
- Камера як джерело фото (AI-MOB-02); без мережі — «Немає з'єднання — спробуйте ще раз», завантажене фото не губиться (AI-MOB-03).
- Повернення з еквайрингу — deep link на картку візиту з актуальним статусом (PAY-MOB-03); push про зміну статусу оплати (PAY-MOB-04).
- Нагадування push про візит (фаза 6, мінімум).

### Закріплений підсумок у застосунку

Застосунок бере факти, правила пропуску, «Будь-який барбер» лише після екрана барбера, дату тільки разом з обраним слотом, режим «Батько + син», коли крок відбувся, і відсутність розбивки ціни з §«Закріплений підсумок» (T-4711a). Цей підрозділ не переписує таблицю фактів і фіксує лише те, що відрізняється на телефоні.

- Pin стоїть під прогресом кроків, у безпечній зоні, над заголовком екрана.
- Один рядок. Якщо він переноситься далі двох рядків, згортаємо до «локація · послуга · барбер», а обраний час лишаємо окремим рядком. «Деталі» розгортає решту. Жодного горизонтального скролу, що обрізає факт.
- Основна кнопка лишається внизу, осторонь індикатора дому.
- Цілі дотику — щонайменше 44 пункти.
- Чіпи попередніх екранів викликають ту саму навігацію, що й back-gesture, разом з очищеннями, які жест уже робить. Back-gesture лишається: pin — другий шлях до попереднього екрана, не заміна жесту.
- Регіон названо «Ваш запис». Одне ввічливе оголошення, коли час обрано: `Обрано 14:00–14:30`.
- Без анімації входу, коли запитано зменшений рух.

```
┌──────────────────────────────┐
│ Крок 3/5                     │
│ [S] Поділ · Стрижка · Олексій│  pin під прогресом
│     сьогодні 14:00–14:30     │  «Коли» — після слота
│ Оберіть час                  │
│ 09:00                        │
│ 09:15                        │
│ [Далі]                       │  внизу, у зоні великого пальця
└──────────────────────────────┘
```
