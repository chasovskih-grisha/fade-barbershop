# Чекліст рев'ю PR — одна сторінка

> Рев'ювер іде зверху вниз; «ні» на будь-якому пункті = change request або письмове обґрунтування в PR. Автоматичні гейти (§0) руками не перевіряються — лише їхні подавлення. Пункт не працює на практиці → це дефект чекліста: виправити тут, не обходити. Джерела: `engineering-principles.md`, `AGENTS.md`, ADR 0019. Дзеркало цього чекліста — PR-шаблон `.github/PULL_REQUEST_TEMPLATE.md` (заповнює автор).

## 0. Автоматичні гейти — зелені до рев'ю

CI тримає сам: LOC < 100 / складність ≤ 10 / параметри ≤ 3 (ADR 0019) · «тільки токени» в UI · типи · піраміда тестів · ковередж-гейти.

- [ ] Кожне подавлення лінтера (`eslint-disable…`) має обґрунтування поруч; «німих» подавлень немає

## 1. Межі і шари (DDD)

- [ ] Домен не імпортує Nest/Prisma/HTTP; залежності всередину (`architecture.md`)
- [ ] Інваріант перевірений в агрегаті, не в контролері («так швидше» — не аргумент)
- [ ] Один агрегат на транзакцію; між контекстами — події через outbox, не спільні entity
- [ ] Команди і функції — мовою домену (`book`, `confirm`, не `setStatus`), терміни — з `ubiquitous-language.md`
- [ ] Зовнішні споживачі залежать від `packages/contracts`, не від внутрішнього домену API

## 2. Порти і надійність (SOLID)

- [ ] Use case = одна причина зміни; нова поведінка = новий обробник/порт, не черговий `case` у switch
- [ ] Зовнішній виклик — вузький порт + ACL: timeout, ретраї; невизначений результат зовнішнього виклику = стан, не виключення
- [ ] Обробник події ідемпотентний: повторна доставка покрита тестом
- [ ] Для зовнішнього провайдера є фейк порту (`Fake…`); мок все-в-одному заборонений

## 3. KISS / YAGNI

- [ ] Немає «про запас»: узагальнених репозиторіїв, універсальних фабрик, плагінів без другого плагіна, конфігу з одним значенням
- [ ] Заборонені патерни не просочилися: CQRS-фреймворки, Event Sourcing, GraphQL, мікросервіс на контекст
- [ ] Запахи з каталогу (`engineering-principles.md`) усунені причиною, не симптомом: дубль правила — один доменний хелпер, deps 4+ — bundle-об'єкт, payload події — `Record<string, unknown>` з явним конструктором

## 4. Тести

- [ ] Піраміда: домен — unit без БД; use case — functional через HTTP; поведінка користувача — e2e GWT
- [ ] Тест = специфікація: ім'я-речення домену, AAA, один assert-блок; без sleep-ів (час — ін'єктований `Clock`), контекстно-безкоштовних fixture, тестів приватних методів
- [ ] Баг-фікс приходить з тестом, що відтворює баг; flaky — виправлений або видалений, не «пропущений»
- [ ] Схема події між контекстами змінилася → snapshot-тест оновлений свідомо

## 5. UI (якщо PR чіпає екрани)

- [ ] Тільки токени: hex/px у екранах відсутні; брак компонента → `packages/ui`, не локальний у екрані
- [ ] Усі стани описані (default / hover / focus-visible / loading / skeleton / error); клікабельне ≥ 44×44
- [ ] Перевірено в браузері / симуляторі, не лише на скріншоті
- [ ] Consent — окремим чекбоксом без попередньої відмітки; деструктивна дія показує наслідок

## 6. Скоуп і наслідки

- [ ] PR = одна мета; «попутних» рефакторингів і змін, яких фаза не просить, немає
- [ ] Опис вказує AC/критерії, які PR закриває; зміна поведінки → оновлені AC / README контексту / ADR
- [ ] Новий бізнес-концепт спершу мав контекст і мову, потім код (`AGENTS.md`)
