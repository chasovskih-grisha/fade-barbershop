# 17. Реферальна програма («приведи друга»)

> Фіча: клієнт ділиться **персональним кодом/посиланням**; друг отримує знижку на **перший візит**, клієнт — винагороду **після завершення** візиту друга. Зростання без рекламного бюджету; працює на існуючих механізмах: знижки — промокоди `discounts`, атрибуція — `crm`, доставка — `notifications`.
>
> Контексти: **без нового контексту**. `crm` — власник зв'язку «хто кого привів» (`InviteCode` на профілі, `ReferredBy` на новому клієнті); `discounts` — referral-промокоди (реферал) і referral-винагорода (запрошувач); `scheduling` — подія `AppointmentCompleted` як тригер винагороди; `notifications` — повідомлення обом сторонам.

## Правило (спільне)

- [ ] **RFR-001.** У кожного клієнта є **персональний реферальний код** (генерується автоматично) і **посилання** `web/r/{code}` (глибоке посилання в mobile). Код веде на `/login`/`/booking` з підставленим кодом; атрибуція фіксується при першому вході/реєстрації друга.
- [ ] **RFR-002.** Знижка **рефералу** — на **перший завершений візит** (за замовчуванням 15%, налаштовується): застосовується автоматично як referral-промокод при записі (DSC-001 фіксація на `AppliedDiscounts`); якщо запис без знижки не відбувся — знижка чекає.
- [ ] **RFR-003.** Винагорода **запрошувачу** — **після `AppointmentCompleted` візиту друга** (не при записі): referral-знижка на наступний візит (за замовчуванням 15%, діє 90 днів) або фіксована сума на сертифікат (за рішенням — див. «Відкриті питання»).
- [ ] **RFR-004.** Атрибуція — **останній торк** у вікні 30 днів: останній реферальний код/посилання до реєстрації друга виграє. Без коду — атрибуції немає (органічна реєстрація). Клієнт не може бути attributed собі (самореферал заборонений).
- [ ] **RFR-005.** Анти-аб'юз (жорсткі правила):
  - винагорода — **тільки за перший завершений візит** приведеного друга (один друг = одна нагорода);
  - реферал має бути **новим** клієнтом (без жодного завершеного візиту на момент реєстрації);
  - **2 no-show поспіль** у друга → винагорода анулюється (правило NSH-006-семантика);
  - повторний друг (той самий телефон/профіль) не дає другої нагороди;
  - адмін може анулювати винагороду з причиною (лог обов'язковий).
- [ ] **RFR-006.** Комбінування: referral-знижка рефералу **заміщує** правило «Перший візит» (DSC-RULE-01) — застосовується вигідніша з двох. Інші правила стеку — загальні DSC-003: referral не комбінується з VIP/промокодом, кап 30% діє. Винагорода запрошувачу — звичайна знижка з тим самим капом.
- [ ] **RFR-007.** Повідомлення: друг — «{ім'я} запрошує до {бренд}: −15% на перший візит» (посилання з кодом); запрошувач — «Друг завершив візит: твоя знижка на наступний візит» (push через `notifications`).
- [ ] **RFR-008.** Скасування візиту друга до завершення → винагорода не нараховується; waitlist-підтверджений візит друга рахується (це звичайний завершений візит, WTL-004).

## Клієнт (web і mobile)

- [ ] **RFR-WEB-01.** У кабінеті: блок «Запросити друга» — персональний код, посилання `web/r/{code}`, кнопки «Поділитися» (share sheet / copy). Mobile: share sheet системний.
- [ ] **RFR-WEB-02.** Кабінет: «Мої запрошення» — список: друг (ім'я, дата реєстрації), статус (записався / завершив візит), винагорода (нарахована / чекає завершення / анульована з причиною).
- [ ] **RFR-WEB-03.** Друг бачить referral-знижку в розбивці запису як звичайну знижку з підписом «За запрошенням {ім'я}» (DSC-006 розбивка).

## Admin

- [ ] **RFR-ADM-01.** Налаштування програми: знижка рефералу (%), винагорода запрошувачу (%/сума), строк дії винагороди (90 днів), вікно атрибуції (30 днів), увімкнути/вимкнути програму.
- [ ] **RFR-ADM-02.** Список рефералів: друг | хто привів | дата реєстрації | статус (записався/завершив) | винагорода (статус, дата нарахування) | дії (анулювати з причиною).
- [ ] **RFR-ADM-03.** Анти-аб'юз огляд: підозрілі патерни (спільні телефони, серії реєстрацій з одного пристрою — якщо доступно; серії no-show рефералів) — список для ручного перегляду, анулювання з логом.
- [ ] **RFR-ADM-04.** Ефективність (розширення ANL): залучено клієнтів за період, CAC referral vs платний трафік, конверсія посилань (кліки → реєстрації → завершені візити), LTV referral-клієнтів vs органічних.

## Відкриті питання

1. **Форма винагороди запрошувачу**: referral-знижка на наступний візит (рекомендовано — повертає в крісло) vs сертифікат на суму vs прогрес лояльності +1 візит (не рекомендовано — плутає лічильник ADR 0009).
2. **Строк дії винагороди**: 90 днів за замовчуванням — достатньо? (тисне на повернення, але не карає).
3. **Ліміт нагород на клієнта**: за замовчуванням без ліміту (поштовх активно ділитися); чи вводити ліміт на рік (наприклад, 10) — рішення при першому сезоні.
4. **Attribution вікно**: 30 днів — industry default; переглянути після перших даних.
