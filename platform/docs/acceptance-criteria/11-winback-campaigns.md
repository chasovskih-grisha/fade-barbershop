# 11. Win-back: сегментні кампанії

> Фіча: засновник створює кампанію по сегменту клієнтів («не був ≥ 60 днів») — одним кліком генерується **персональний промокод** (`discounts`) і сегмент отримує **push** (`notifications`). Найвигідніший маркетинг малої точки: повернення «заснулих» клієнтів майже безкоштовне на існуючих механізмах.
>
> Контексти: **без нового контексту**. Кампанія — оркестрація: сегменти за даними `crm` (профілі, останні візити, лояльність), самі знижки — звичайні промокоди в `discounts`, доставка — `notifications`, ефективність — `analytics` (розширення ANL).

## Правило (спільне)

- [ ] **WNB-001.** Кампанія = **сегмент + промокод + повідомлення**. Адмін обирає сегмент, задає знижку (тип/значення/термін) і текст push — і відправляє. Нових моделей знижок немає: код створюється в `discounts` як звичайний промокод і застосовується звичайним шляхом (DSC-WEB-01…03) з усіма правилами стеку DSC-003.
- [ ] **WNB-002.** Сегменти v1 (за даними CRM): «не був ≥ N днів» (за замовчуванням 60), «перший візит був, другого немає», «колишні VIP», «прогрес лояльності ≥ 4 з 7» (майже заробили безкоштовний). Кількість клієнтів у сегменті показується **до відправки** (прев'ю).
- [ ] **WNB-003.** Промокод кампанії **персональний**: один код-шаблон кампанії, ліміт — **1 використання на клієнта** сегмента (не загальний), діє N днів з відправки (за замовчуванням 14). Інші клієнти (не з сегмента) кодом скористатися не можуть.
- [ ] **WNB-004.** Доставка — push через `notifications` (фаза 7): короткий текст кампанії + код + дедлайн. SMS/email — поза цією фічею (окреме рішення, див. «Відкриті питання»).
- [ ] **WNB-005.** До сегмента не потрапляють: клієнти без профілю (анонімні walk-in, WALK-003), клієнти з відключеним push, і клієнти, у яких **уже є активний запис** (щоб не «повертати» того, хто вже йде).
- [ ] **WNB-006.** Анти-спам: одне повідомлення на клієнта на кампанію; повторна кампанія по тому ж сегменту допускається не частіше, ніж раз на N днів (за замовчуванням 30).
- [ ] **WNB-007.** Кожна відправка фіксує подію на клієнта (`CampaignSent`), використання коду видно як звичайне `AppliedDiscounts` — цього достатньо, щоб `analytics` порахував ефективність без нових потоків.

## Admin

- [ ] **WNB-ADM-01.** Розділ «Кампанії»: список (назва, сегмент, промокод, відправлено N, використань, статус), кнопка «Нова кампанія».
- [ ] **WNB-ADM-02.** Форма кампанії: назва; сегмент (select з живим рахунком «клієнтів у сегменті: N»); знижка (тип %/сума, значення, діє N днів); текст push (~140 символів, прев'ю); підтвердження перед відправкою («Відправити N клієнтам?»).
- [ ] **WNB-ADM-03.** Картка кампанії після відправки: відправлено / використань коду / виручка з кодом; статус активна/завершена (за терміном коду).
- [ ] **WNB-ADM-04.** Ефективність (розширення ANL): конверсія кампанії (використання / відправлено), зіставлення з ANL-006 (злив через знижки) — ROI кампанії видно, а не тільки факт відправки.

## Відкриті питання

1. **Канал**: push-only у v1 фічі (рекомендовано) чи додати SMS для «не був ≥ 90 днів» — платний канал, окреме рішення.
2. **Інтервал між кампаніями** (WNB-006): 30 днів за замовчуванням — достатньо?
3. **Сегмент «дні народження»**: не робити зараз; майбутнє розширення того ж механізму.
