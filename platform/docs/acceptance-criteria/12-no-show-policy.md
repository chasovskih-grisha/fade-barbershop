# 12. No-show: політика нез'явок

> Фіча: нез'явка — головний вбивця економіки крісла. Система **автоматично** фіксує no-show, подія розходиться по контекстах (CRM, лояльність, аналітика, push), а правила повторного запису стримують зриви. Депозит-механіка (PAY-WEB-07) уже існує — ця фіча робить її автоматичною.
>
> Контексти: **без нового контексту**. `scheduling` — авто-правило і подія `AppointmentNoShowed` (вже в плані подій), `billing` — утримання/повернення депозиту (PAY-WEB-07, PAY-ADM), `crm` — прапор в історії клієнта, `analytics` — rate (ANL-004 існує).

## Правило (спільне)

- [ ] **NSH-001.** No-show = клієнт не з'явився і не скасував до початку візиту. Фіксується **автоматично** через X хвилин після часу слота (за замовчуванням 15), якщо візит досі в статусі «Очікує/Підтверджено», — або **вручну** барбером/адміном раніше (кнопка на картці візиту).
- [ ] **NSH-002.** Авто-правило не спрацьовує, якщо візит уже `in_progress` / `completed` / `cancelled` / `rescheduled`. Візит, який так і не був підтверджений клієнтом, теж стає no-show (записався і зник).
- [ ] **NSH-003.** Депозит при no-show **не повертається** — уже вирішено (PAY-WEB-07). Тут фіксується, що це відбувається **без ручної дії**: авто-фіксація no-show і утримання депозиту — один потік.
- [ ] **NSH-004.** Подія `AppointmentNoShowed` розходиться: `crm` — прапор у історії клієнта; `loyalty` — візит не рахується (інваріант 9); `analytics` — rate (ANL-004); `notifications` — push клієнту (NSH-007).
- [ ] **NSH-005.** Rate no-show уже рахується по барберу (ANL-004); тут додається розріз **по каналу запису** (online з депозитом / online без / walk-in не має no-show за визначенням) — щоб бачити, що саме стримує зриви (розширення ANL).
- [ ] **NSH-006.** Правило повторного запису: клієнт з **2 no-show за 90 днів** при наступних записах бачить вимогу **повної передоплати** (депозит 100% — той самий флоу, визнаний у `01` як конфігурація депозиту). Після одного успішного візиту повертається звичайний депозит (30%). Адмін може зняти обмеження вручну (NSH-ADM-02).
- [ ] **NSH-007.** Push клієнту при no-show: нейтральний текст («Вас не було на записі {дата}. Записатися знову») — без штрафних формулювань. Умова повної передоплати показується клієнту при записі як звичайний текст правил (PAY-WEB-07), не як покарання.

## Барбер (mobile)

- [ ] **NSH-BAR-01.** У календарі дня візит після авто-фіксації виглядає «No-show»; є кнопка «Позначити no-show» одразу (не чекаючи X хвилин).

## Admin

- [ ] **NSH-ADM-01.** Налаштування: хвилини авто-фіксації (15), вікно порогу (90 днів), кількість no-show для обмеження (2), увімкнути/вимкнути правило повної передоплати.
- [ ] **NSH-ADM-02.** У картці клієнта (`crm`): історія no-show (дати), активне обмеження (так/ні), кнопка «Зняти обмеження» з причиною (лог).
- [ ] **NSH-ADM-03.** Зняття no-show (клієнт пояснив, був у лікарні): адмін прибирає прапор — депозит повертається вручну (refund — тригер PAY-005(б), ідемпотентність PAY-006), rate перераховується. Лог обов'язковий.

## Відкриті питання

1. **Push при no-show** (NSH-007): надсилати щоразу чи лише перший (не докоряти постійному клієнту). Рекомендація: щоразу, текст нейтральний.
2. **Пороги** (NSH-006): 2 за 90 днів — стартові значення; переглянути після 2 місяців даних ANL-004.
