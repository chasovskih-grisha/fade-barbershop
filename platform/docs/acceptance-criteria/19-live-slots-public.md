# 19. Живі слоти на публічних сторінках

> Фіча: блок «вільні вікна на наступні 7 днів» прямо на `/services`, `/locations/{code}` і сторінках барберів — гість бачить реальну доступність **до** входу і без старту флоу запису. Знімає найбільше тертя конверсії: між «побачив ціну» і «побачив, коли вільно».
>
> Контексти: **без нового контексту**. `scheduling` публікує **read-only проекцію** доступності (OHS для web-гостя); сайт лише показує. Критичний принцип: **віджет ніколи не бронює** — це картина, не поверхня запису (ADR не потрібен: нової моделі немає, є read-model існуючих слотів).

## Правило (спільне)

- [ ] **LST-001.** Проекція **read-only**: клік по вікну/дню веде у `/booking` з підставленим контекстом (локація/послуга/барбер + дата) на крок 3 (слоти), де слот **перевіряється заново** тими самими правилами, що й звичайний запис. Розбіжність «показано вільно, а забронювався інший» — обробляється звичайним флоу (слот зайнятий → вибір іншого або waitlist), не помилка.
- [ ] **LST-002.** Вміст: **7 днів** від сьогодні; на день — кількість вільних вікон + **3 найближчі часи** під тривалість конкретної послуги (90 хв `father-son` — окремі вікна від 50 хв). Режим «Будь-який барбер» — агрегат по всіх барберах локації + чипси по барберах.
- [ ] **LST-003.** «Вільне вікно» = та сама валідація, що запис: `Availability` барбера + `OpeningHours` локації + інваріант 2 крісел, мінус тривалість послуги. Слоти під waitlist-hold **не рахуються** вільними (ADR 0012); зайняті walk-in — зайняті.
- [ ] **LST-004.** Кеш 60 с (Redis) на ключ (локація, послуга, барбер-фільтр); без WebSocket у v1. Застарілість прийнятна **бо проекція не бронює** (LST-001) — флоу перевіряє заново.
- [ ] **LST-005.** Деградація: `scheduling` недоступний → блок просто ховається, сторінка працює далі (без помилок на публічних сторінках). У payload — тільки агрегати (дні, кількості, часи); жодних персональних даних. SEO: дані волатильні — блок не індексується (fragment/ISR 60 с).
- [ ] **LST-006.** Порожній стан: «На найближчі 7 днів вільних вікон немає» + CTA **waitlist** «Повідомити, якщо звільниться» (WTL-WEB-01, фаза 17; до неї — підказка «зателефонуйте нам»).
- [ ] **LST-007.** Вимкнені об'єкти не з'являються: локація (MNG-ADM-02), послуга (MNG-ADM-10/12), барбер (MNG-ADM-05/06) — блок будується тільки з активних; вимкнення в адмінці прибирає блок з публічної сторінки негайно (в межах кешу).
- [ ] **LST-008.** Ендпоінт: `GET /public/availability?location=&service=&barber=` — публічний read-model у `scheduling` (OHS, тільки агрегати); окремий від внутрішніх API запису, без авторизації.

## Web (публічні сторінки)

- [ ] **LST-WEB-01.** `/services`: на картці кожної послуги — стрічка «Найближчі вікна: сьогодні 14:30 · 16:00 · завтра 10:00» (за тривалість послуги, по локації v1); клік → `/booking` з послугою і датою (кроки 1→3).
- [ ] **LST-WEB-02.** `/locations/{code}`: блок «Вільні вікна на 7 днів» — 7 колонок-днів (кількість), клік по дню → найближчі часи; CTA → `/booking` з локацією і днем. Селектор послуги всередині блоку (за замовчуванням популярна).
- [ ] **LST-WEB-03.** `/barbers/{slug}`: стрічка «Найближчі вікна у {барбер}» (7 днів, агрегат по послугах барбера); клік → `/booking` з барбером і днем (крок 2→3). На `/barbers` (список) — без слотів, щоб не перевантажувати.
- [ ] **LST-WEB-04.** Стани: loading — скелетони стрічки; «сьогодні вільних немає» — підсвітка найближчого дня з вікнами («Наступні вікна — у середу»); помилка/таймаут — блок схований (LST-005).

## Відкриті питання

1. ~~**Головна сторінка**~~ — **вирішено** (головна специфікована, `web-screens.md` §0): стрічка входить у hero головної — компактний формат за `LST-002` (популярна послуга, єдина локація v1), клік → `/booking` з підставленим контекстом; стани — `LST-WEB-04`.
2. **Mobile (гостьовий контур)**: той самий блок у додатку до логіну (блог/локації) — розширення після web; в додатку запис і так за OTP.
3. **Реалтайм**: WebSocket push у v2, якщо дані покажуть, що 60-секундна застарілість шкодить конверсії (розбіжності лічаться в ANL як розширення).
