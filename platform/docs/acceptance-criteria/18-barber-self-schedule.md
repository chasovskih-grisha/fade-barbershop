# 18. Барбер сам керує своїм графіком

> Фіча: барбер редагує **власні вікна прийому і вихідні** з мобільного додатка — у межах політики, яку задає засновник. Знімає адмін-навантаження при зростанні мережі: щотижневі корекції і відпустки — без звернень до адміна. Модель не змінюється: той самий `Availability` у `scheduling`, що редагує адмінка (§2.3 `admin-screens.md`), — з'являється **другий письменник за політикою доступу**.
>
> Контексти: **без нового контексту**. `scheduling` — агрегат `Availability` (спільний з MNG-ADM-07…09), подія `AvailabilityChanged` (джерело: `barber`/`admin`); `identity` — прапорець дозволу на барбері. Політика наявних візитів при недоступності — **ADR 0056** (маркування → конфлікти → рішення засновника), не автоматичний перенос.

## Правило (спільне)

- [ ] **SCH-001.** Делегування — **за прапорцем на барбері** (адмін вмикає/вимикає у формі барбера, MNG-ADM-05-семантика). За замовчуванням вимкнено. Без дозволу барбер графік **бачить**, але не редагує.
- [ ] **SCH-002.** Барбер редагує ті самі дані, що адмінка: тижневий шаблон (вікна «з–до», макс. 2 на день, крок 15 хв, без перетинів — валідація як §2.3) і **одноразові вихідні** (конкретна дата або діапазон: відпустка, лікарняний).
- [ ] **SCH-003.** Вікна барбера — **в межах `OpeningHours` локації** (жорстко для self-service, на відміну від попередження в адмінці §2.3); якщо адмін явно дозволив вихід за години (прапорець на барбері) — обмеження знімається.
- [ ] **SCH-004.** **Зміна ніколи не скасовує і не переносить заброньовані візити.** Збереження вихідного/відпустки одразу застосовує `UnavailableDay`: нові записи й слоти в інтервалі блокуються, а кожен наявний візит стає відкритим `ShiftConflict` (ADR 0056). Барбер бачить список конфліктів (клієнт · час · послуга), але **не має права** переносити/скасовувати (це права адміна, MNG-ADM-15) → кнопка «Повідомити адміна» + конфлікти видно обом. Засновник вирішує кожен візит окремо (переносить або скасовує) і клієнт отримує одне повідомлення.
- [ ] **SCH-005.** Зміни, що не зачіпають заброньовані слоти, застосовуються **одразу**: слоти стають доступними/недоступними в записі миттєво (валідація запису — фаза 4, без кешування).
- [ ] **SCH-006.** Адмін може редагувати графік будь-якого барбера завжди (MNG-ADM-07…09 без змін); зміна адміна перекриває self-service. Кожна зміна логується: хто (барбер/адмін), коли, що змінилось (старе → нове).
- [ ] **SCH-007.** Барбер бачить свою **історію змін графіка** (джерело, дата) — щоб розуміти, хто зробив поточний графік.
- [ ] **SCH-008.** Подія `AvailabilityChanged` (з джерелом) — для аудиту; `analytics` — опційно (кореляція зміни графіка і завантаженості, ANL-002).

## Барбер (mobile)

- [ ] **SCH-BAR-01.** Екран «Мій графік»: тижневий редактор (7 рядків: вихідний-toggle або вікна «з–до» + «Додати вікно»), розділ «Вихідні/відпустка» (список діапазонів + «Додати»), кнопка «Зберегти».
- [ ] **SCH-BAR-02.** Конфлікти при збереженні: банер «N візитів чекають рішення засновника» + список конфліктів + кнопка «Повідомити адміна» (SCH-004). Інтервал уже застосований: нові записи заблоковані, наявні візити не змінені. Збереження одразу відображається в календарі дня.
- [ ] **SCH-BAR-03.** Історія змін графіка (SCH-007) і статус дозволу: без дозволу — екран лише для перегляду з поясненням «Редагування графіка — у адміна».

## Admin

- [ ] **SCH-ADM-01.** Прапорець «Барбер керує графіком сам» у формі барбера (§2.2); зміна дозволу логується.
- [ ] **SCH-ADM-02.** Журнал змін графіків: барбер | дата зміни | джерело (barber/admin) | що змінилось; фільтр по барберу.
- [ ] **SCH-ADM-03.** Конфлікти від барбера: push/запис у журналі «барбер просить вирішити конфлікти» → перехід у редактор графіка (§2.3) з підсвіченими конфліктними візитами.

## Відкриті питання

1. **Строк попередження** для днів з візитами: зараз блокування конфліктами (SCH-004) — достатньо; чи вводити додатковий мінімальний строк (наприклад, зміни на завтра — лише через адміна). Рекомендація: без додаткового строку, подивитись на практиці.
2. **Радіус self-service**: чи дозволити барберу самому міняти *локацію* роботи (якщо працює на двох точках, фаза 9) — поки ні, тільки графік.
3. **Push підтвердження адміну** при кожній зміні барбера: спам чи контроль. Рекомендація: без push, тільки журнал (SCH-ADM-02).
