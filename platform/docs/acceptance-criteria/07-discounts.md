# 07. Знижки (промокоди, правила, VIP)

> Фіча: знижки на послуги трьох типів — **промокоди** (клієнт вводить код), **автоматичні правила** (перший візит, непікові години, дні тижня), **VIP-рівень** клієнта (стоїть на картці в `crm`). Застосовуються **при записі** і фіксуються на візиті (`AppliedDiscounts`, механізм — ADR 0007).
>
> Контекст: **`discounts`** (новий, Supporting) — визначення знижок; `scheduling` зберігає застосовані знижки на `Appointment`; `billing` платить `FinalPrice`. Ціни-основи — `AgreedPrice` (ADR 0006).

## Правило (спільне для всіх поверхонь)

- [ ] **DSC-001.** Знижки застосовуються **при записі** і фіксуються на візиті (`AppliedDiscounts`); зміна або вимкнення коду/правила/VIP-рівня після запису не впливає на існуючі візити (ADR 0007).
- [ ] **DSC-002.** Типи знижок: промокод, автоматичне правило, VIP-рівень. Значення: **% від `AgreedPrice`** або **фіксована сума (UAH)**.
- [x] **DSC-003.** **Рішення: обмежений стек знижок.** Комбінуватись можуть лише **VIP-рівень + промокод** (і лише ця пара). Автоматичні правила (перший візит, непікові години) — між собою **одна найвигідніша** і не комбінуються з VIP/промокодом. **Сумарна знижка ≤ кап** (за замовчуванням **30%** від `AgreedPrice`, налаштовується адміном — DSC-ADM-06); фіксовані знижки (грн) для капу вважаються як % від `AgreedPrice`. Клієнт бачить **кожну застосовану знижку окремо** в розбивці (DSC-006).
  - **Чому так**: VIP — нагорода за лояльність, промокод — кампанія; їх комбінація типова для утримання. Кап 30% тримає маржу преміум-сегменту: повний стек (будь-які комбінації) роз'їдає економіку точки, а «тільки одна знижка» знецінює промокоди для постійних клієнтів.
- [ ] **DSC-004.** `FinalPrice` = `AgreedPrice` − знижка, **≥ 0 грн**; сума ніколи не від'ємна (фіксована знижка більша за ціну обрізається до 0).
- [ ] **DSC-005.** Безкоштовний візит лояльності — пріоритет: `FinalPrice = 0`, знижки не застосовуються і не комбінуються з бонусом (оновлює `LYL-004`).
- [ ] **DSC-006.** Клієнт бачить розбивку **до підтвердження** запису: базова ціна, знижка (тип/код), підсумок до оплати.
- [ ] **DSC-013.** **Промокод або правило на 100% дозволені**: `FinalPrice = 0`. Такий візит проходить як **безкоштовний з причиною `full_discount_promo`** — PAY-003: без `Payment`, без чека, без депозиту (депозит = 30% × 0 = 0). Клієнт бачить рядок «Знижка 100% (промокод)» і підсумок «0 ₴» на екрані підтвердження; бейдж «Цей візит безкоштовний» — як у LYL-WEB-02. Промокод зараховується як використаний при записі (DSC-001); скасування візиту повертає ліміт (відкрите питання 2).

## Промокоди — клієнт (web і mobile)

- [ ] **DSC-WEB-01.** У формі запису є поле «Промокод»; після введення — миттєва валідація і показ знижки в розбивці до підтвердження.
- [ ] **DSC-WEB-02.** Помилки (укр.): «Код не дійсний», «Термін дії закінчився», «Ліміт використань вичерпано»; невірний код не блокує запис — просто не дає знижку.
- [ ] **DSC-WEB-03.** Код нечутливий до регістру, пробіли ігноруються (`instagram10` = `INSTAGRAM10`).
- [ ] **DSC-MOB-01.** Ті самі сценарії, що DSC-WEB-01–03, у мобільному флоу запису.

## Автоматичні правила (без дій клієнта)

- [ ] **DSC-RULE-01.** «Перший візит»: клієнт без жодного завершеного візиту отримує знижку (за замовчуванням 10%; налаштовується).
- [ ] **DSC-RULE-02.** «Непікові години»: візит у заданий період (дні + години, наприклад Пн–Чт 10:00–13:00) отримує знижку; перевіряється за обраним слотом і показується до підтвердження.
- [ ] **DSC-RULE-03.** Правила вмикаються/вимикаються адміном; зміна не впливає на вже створені візити (DSC-001).

## VIP-рівень клієнта

- [ ] **DSC-VIP-01.** Адмін встановлює рівень знижки на картці клієнта (`crm`) — % або фіксована сума; застосовується автоматично до всіх записів клієнта.
- [ ] **DSC-VIP-02.** Клієнт бачить свій рівень і знижку в профілі та в розбивці запису (опційно в v1).
- [ ] **DSC-VIP-03.** VIP-знижка не накладається на промокод/правило — діє найвигідніша (DSC-003).

## Admin

- [ ] **DSC-ADM-01.** Промокоди: список і форма — код (унікальний), тип (%/сума), значення, термін дії, загальний ліміт використань, застосовність (усі послуги або конкретні), активний/вимкнений. Вимкнення діє для нових записів миттєво.
- [ ] **DSC-ADM-02.** Правила: список і форма — умова (перший візит / непікові години з днями і часом), значення, активне; валідація дублікатів умов (попередження).
- [ ] **DSC-ADM-03.** VIP-рівні: поле знижки на картці клієнта; зміна логується (хто, коли, причина).
- [ ] **DSC-ADM-04.** Статистика: використання кодів (кількість, сумарна знижка), застосування правил, сумарна знижка за період по локаціях — з `AppliedDiscounts` візитів.
- [ ] **DSC-ADM-05.** У картці візиту і в «Оплатах» видно розбивку: базова ціна, застосовані знижки (тип/код, сума), підсумок; чек формується на `FinalPrice`.
- [ ] **DSC-ADM-06.** Кап сумарної знижки (за замовчуванням 30%) налаштовується адміном; розбивка на екрані підтвердження показує кожну застосовану знижку окремо (VIP, промокод) і сумарну.
- [ ] **DSC-ADM-07.** У «Оплатах» і статистиці знижок візити з `FinalPrice = 0` від 100% кодів/правил видно з причиною `full_discount_promo` (поряд з `loyalty` — LYL-ADM-05); розбивка показує код і суму 100%.

## Відкриті питання

1. **«Перший візит»** (DSC-RULE-01): рахувати завершені візити чи всі створені.
2. **Повернення ліміту коду** при скасуванні візиту: так (за замовчуванням).
3. **Барбер і знижки**: як PAY-BARBER-01 — прапорець «зі знижкою» без сум, за рішенням; за замовчуванням барбер нічого не бачить.
