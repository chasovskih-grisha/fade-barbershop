# Приймальні критерії (Acceptance Criteria)

> Що саме має вміти система, щоб фіча вважалась прийнятою. Критерії згруповані по **фічах**, усередині — по **поверхнях** (web, mobile, admin). Це вимоги до поведінки, не до екранів: екрани описані в `docs/products.md`.

## Формат

- Кожен критерій — перевірний стан системи: `- [ ]` означає «ще не прийнято», `- [x]` — «прийнято/підтверджено».
- ID критерію: `{ФІЧА}-{ПОВЕРХНЯ}-{НН}`, наприклад `PAY-WEB-01`. Використовується в трекінгу, тестах і реліз-нотатках.
- Поверхні: **WEB** (сайт, кабінет клієнта), **MOB** (mobile, клієнт), **BAR** (mobile, барбер), **ADM** (admin засновника).
- Де потрібна послідовність станів — Given/When/Then однією стрічкою.
- Терміни — з `docs/ubiquitous-language.md` (не вигадувати синоніми в коді й ТЗ).

## Де це в роадмапі

- **Оплата** — фаза 8 (`billing`). Не блокує запис на старті: у v1 запис може бути без онлайн-оплати, оплата — окремою фічею.
- **Референс зачіски в записі** — фаза 4 (`scheduling`), клієнтські екрани — фази 3/6, барбер бачить із фази 7.
- **AI-підбір зачіски** — фаза 10 (`haircut-ai`), дві частини: генерація (A) — паралельно з фазами 3–6 і не блокує v1; прив'язка до візиту і перегляд барбером (B) — після Scheduling (фаза 4) і барбера в mobile (фаза 7). Рекомендація по позиції — у `docs/roadmap.md`.
- **Управління в адмінці** — фаза 2 (каркас admin, CRUD локацій/послуг/персоналу); графіки і календар — фаза 4; клієнти — фаза 5.
- **Бонус «кожен 7-й візит»** — фаза 11 (`loyalty`), дві частини: A — лічильник/прогрес (може в v1, не потребує оплату), B — безкоштовний візит (`FinalPrice = 0`, фаза 8; до першого анонсу бонусу). Механіка — ADR 0009.
- **Відгуки** — фаза 12 (`feedback`), дві частини: A — приватні (опційно в v1; залежать від завершених візитів — фаза 4 і push — фаза 7), B — публічні (фаза 25, за власними критеріями).
- **Знижки** — фаза 13 (`discounts`), три незалежні частини: A — VIP (`crm`, фаза 5), B — правила («перший візит» рекомендовано в v1 як acquisition-важіль), C — промокоди (перед фазою 18 win-back). Спільний механізм — ADR 0007, ціни (фаза 2), запис (фаза 4).
- **Аналітика** — фаза 14 (`analytics`), **входить у v1 як жорстка вимога**: паралельно з фазами 6–8, фіналізація разом з оплатами (фаза 8).
- **Walk-in** — фаза 15, **входить у v1 (операційно необхідний)**: після фази 4 (scheduling), барбер — фаза 7, оплата на місці — фаза 8.
- **«Батько + син»** — фаза 4 (`AppointmentParty`, ADR 0011), **входить у v1**: екрани запису — фази 3/6, барбер — фаза 7, walk-in партії — фаза 15.
- **No-show-політика** — фаза 16 (одразу після v1): авто-фіксація на фазі 4, депозит — фаза 8, push — фаза 7.
- **Waitlist** — фаза 17 (одразу після v1): події звільнення — фаза 4, push — фаза 7; механіка — ADR 0012.
- **Win-back-кампанії** — фаза 18: CRM — фаза 5, промокоди — фаза 13, лояльність — фаза 11, push — фаза 7.
- **Публічна галерея** — фаза 19 (`portfolio`): барбер у mobile — фаза 7, AI-варіанти — фаза 10, фото відгуків — фаза 12.
- **Подарункові сертифікати** — фаза 20 (`gift-certificates`): web покупця — фаза 3, еквайринг/Checkbox — фаза 8, оплата на місці — фаза 15; механіка — ADR 0013.
- **Реферальна програма** — фаза 21: атрибуція — `crm` (фаза 5), referral-знижка — `discounts` (фаза 13), тригер — `AppointmentCompleted` (фаза 4); механіка — ADR 0014.
- **Онлайн-магазин** — shop-lite (v1.1) і фаза 27 (`shop` у моноліті): каталог/сток — з адмін-каркаса фази 2, оплата — фаза 8 (еквайринг), push — фаза 7; спільна авторизація і домени — ADR 0017; механіка — `docs/online-shop.md`.
- **Self-service графіка** — фаза 22: той самий `Availability` (фаза 4), прапорець дозволу на барбері (фаза 2), барбер у mobile — фаза 7.
- **Живі слоти на сайті** — фаза 23, рекомендовано в v1: read-only проекція `scheduling` (фаза 4), сторінки сайту — фаза 3.
- **GBP-інтеграція** — фаза 24: поля на локації (фаза 2), push завершення — фаза 7; конфігураційна (посилання), без API Google.
- **Публічні відгуки** — фаза 25 (розширення фази 12): активує FDB-006/FDB-ADM-04; згода — у формі відгуку (FDB-WEB-05), сторінки сайту — фаза 3.
- **SEO-сторінки послуг** — фаза 26 (розширення фази 3): дані з `catalog` (фаза 2); варіанти по локаціях — з фазою 9.
- **Асистенти** — фаза 28 (`assistants`), **поза v1, після M4/M5 за рішенням засновника**: шар над ready use cases — потребує канали messaging (фаза 7) і дані (фази 4–5, 11–14); механіка — ADR 0020.

Точна відповідність «критерій → фаза → контекст»: **[traceability.md](traceability.md)**. Конкретні AC-гейти запуску CLT-01 — **чеклист запуску v1** наприкінці `docs/roadmap.md`.

## Відкриті рішення (product, не технічні)

Зафіксовані по файлах у розділах «Відкриті питання». Змінюють критерії, тому виносяться явно. **Вирішені**: депозит 30% при записі, решта на місці (див. `01`); відгуки приватні в першому релізі (див. `06`, FDB-006); безкоштовний візит і 100% промокод без фіскального чека (див. `05`, LYL-007; `01`/`07`, PAY-003 + DSC-013); стек знижок — лише VIP + промокод з капом 30% (див. `07`, DSC-003); лояльність рахує всі завершені візити без класифікації послуг (див. `05`, LYL-001; ADR 0009); вікно скасування депозита — дефолт 4 години, єдине на мережу в v1, снепшот політики на запис, по барберу — відхилено (див. `01`, PAY-ADM-09).

1. Чи бачить барбер прапорець «оплачено» (без сум) у картці візиту (див. `01`).
2. Кількість AI-варіантів, ліміти генерацій, дедлайн редагування референсу (див. `02`, `03`).
