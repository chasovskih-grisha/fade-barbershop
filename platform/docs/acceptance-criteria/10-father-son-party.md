# 10. «Батько + син» — пакет на двох з режимом виконання

> Фіча: клієнт бронює `father-son` і обирає `FulfillmentMode`: по черзі на одному барбері або паралельно на двох кріслах. Одна ціна пакета, два стіна-годинники. Агрегат `AppointmentParty` (ADR 0011).
>
> Контекст: `scheduling` (+ `catalog`, `billing`, `loyalty`, `crm`).
>
> Роадмап: **фаза 4**, входить у v1 (CLT-01, школа поруч). Walk-in тієї ж моделі — фаза 15. Екрани: `docs/booking-flow.md`.

## Правило

- [ ] **PARTY-001.** `father-son` — один `ServiceId`. Ціна пакета з матриці локації, **однакова** для `sequential` і `parallel`. Не два SKU.
- [ ] **PARTY-002.** Після вибору послуги клієнт **обов’язково** обирає режим, перш ніж барбера й слот. Без режиму «Далі» неактивне.
- [ ] **PARTY-003.** `sequential`: один барбер, одне крісло, стіна-годинник **90 хв**, порядок ніг фіксований — спочатку син (`junior-haircut` 45 хв), потім батько (`signature-haircut`).
- [ ] **PARTY-004.** `parallel`: два різні барбери, два крісла, спільний старт, стіна-годинник **50 хв**. Нога сина 45 хв, батька 50 хв. Той самий барбер на обидві ноги — заборонено.
- [ ] **PARTY-005.** Parallel пропонується лише якщо на слот є два активні барбери локації і два вільні крісла. Інакше режим disabled з текстом на кшталт «Зараз один майстер — оберіть чергу або інший час». Sequential лишається.
- [ ] **PARTY-006.** На локації з 2 кріслами картка parallel попереджає: «Займете обидва крісла, салон на цей час лише для вас».
- [ ] **PARTY-007.** `book` створює `AppointmentParty` з двома `PartyLeg` в **одній** транзакції. Не буває партії з однією ногою. Скасування і перенесення — усієї партії.
- [ ] **PARTY-008.** `AgreedPrice` і `FinalPrice` — на партії (ADR 0006/0007). Одна оплата, один чек, рядок «Батько + син». Ноги не мають клієнтської ціни.
- [ ] **PARTY-009.** Ім’я сина (`CompanionName`) обов’язкове. Акаунта в дитини в v1 немає. Вік > 12 — не цей SKU (підказка записати дві дорослі стрижки).
- [ ] **PARTY-010.** Лояльність: `AppointmentCompleted` інкрементує лічильник **лише** по нозі батька (`ClientProfile` записника). Нога сина лояльність не чіпає. Партія ≠ два візити батька.
- [ ] **PARTY-011.** Зайнятість крісел: sequential тримає одне крісло 90 хв (друге вільне для інших клієнтів). Parallel тримає два крісла від старту; крісло сина звільняється після 45 хв.

## Web (кабінет / `/booking`)

- [ ] **PARTY-WEB-01.** Після картки `father-son` — екран режиму: дві картки «По черзі · один барбер · 90 хв» і «Одразу · два крісла · ~50 хв». Ціна на обох однакова.
- [ ] **PARTY-WEB-02.** Sequential: екран барбера як у звичайному флоу (`booking-flow` крок 2). Сітка слотів — кроки, де 90 хв вільні на обраному барбері й кріслі.
- [ ] **PARTY-WEB-03.** Parallel: замість одного барбера — «Будь-які два вільні» (default) або вибір двох різних. Сітка — старти, де обидві ноги містяться. Немає старту — підказка змінити режим або дату.
- [ ] **PARTY-WEB-04.** Екран зачіски/коментаря — дві секції: батько і син. Референс опційний на кожну ногу. Ім’я сина — поле в секції сина.
- [ ] **PARTY-WEB-05.** Підсумок (екран 5): режим, імена, хто стриже кого, час закінчення партії (не лише старт), одна `FinalPrice`.

## Mobile клієнт

- [ ] **PARTY-MOB-01.** Той самий вибір режиму окремим екраном після послуги; copy як WEB.
- [ ] **PARTY-MOB-02.** Push-нагадування — на партію (один час приходу), не двічі.

## Барбер

- [ ] **PARTY-BAR-01.** У календарі барбер бачить **свою ногу**: «Батько + син · син» або «· батько», ім’я, тривалість ноги.
- [ ] **PARTY-BAR-02.** `complete` ноги не завершує партію, доки друга нога не `complete`. Статус партії видно на картці.
- [ ] **PARTY-BAR-03.** Walk-in `father-son`: той самий вибір режиму. Якщо друге крісло зайняте — parallel недоступний (PARTY-005).

## Адмінка

- [ ] **PARTY-ADM-01.** Календар мережі показує партію як зв’язані блоки на одному або двох стовпцях барберів. Перенесення/скасування — партії (підтвердження: «скасується запис батька і сина»).
- [ ] **PARTY-ADM-02.** Картка: режим, обидві ноги, одна розбивка ціни на партії.

## Відкриті питання

1. Комісія parallel: пропорція 750:600 від суми пакета (рекомендація ADR 0011) — підтвердити в розрахунковій відомості, не в UI клієнта.
2. Дитячий `ClientProfile` / сімейний акаунт — не v1.
3. Зміна порядку ніг sequential «батько першим» — не v1.
