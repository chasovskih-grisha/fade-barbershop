# 09. Walk-in: живий запис на місці

> Фіча: барбер або адмін створює візит «на місці» за ~10 секунд — **без OTP, без підтвердження, без депозиту**; той самий календар (`scheduling`), CRM (`crm`) і каса (`billing`). **Операційно необхідний для v1**: барбершоп не працює без walk-in.
>
> Контексти: `scheduling` (команда `CreateWalkInAppointment`), `crm` (клієнт), `billing` (оплата на місці: готівка/картка через POS). **Нового контексту немає** — це флоу поверх існуючих, ті самі агрегати і події.

## Правило (спільне)

- [ ] **WALK-001.** Walk-in створює **персонал** — барбер (mobile) або адмін (web), не клієнт. OTP не потрібен, підтвердження немає: візит одразу з'являється в календарі з бейджем «Walk-in».
- [ ] **WALK-002.** Час = «зараз» або найближчий вільний слот; валідація та сама, що для онлайн-запису: `Availability` барбера, `OpeningHours` локації, інваріант 2 крісел.
- [ ] **WALK-003.** Клієнт: пошук за телефоном (існуючий `ClientProfile`) АБО новий — ім'я + телефон (опційно). Без телефону — **анонімний**: у візиті є, але без лояльності і push (див. «Відкриті питання»).
- [ ] **WALK-004.** Депозит не стягується (клієнт уже в кріслі). Оплата — **на місці**: готівка або картка POS; чек Checkbox на суму `FinalPrice` (флоу PAY-ADM-04/07).
- [ ] **WALK-005.** Подальший життєвий цикл **той самий**: `start → complete` → події → CRM-історія; відгук і лояльність — якщо клієнт ідентифікований (WALK-003).
- [ ] **WALK-006.** Знижки до walk-in застосовуються автоматично (правила/VIP, DSC-003); промокод — якщо клієнт назвав код (вводить персонал).

## Mobile — барбер

- [ ] **WALK-BAR-01.** Кнопка **«Walk-in»** на календарі дня → швидка форма: послуга (select), клієнт (пошук за телефоном / «новий»: ім'я, телефон опц.), час (за замовчуванням «зараз»), коментар (опц.).
- [ ] **WALK-BAR-02.** Створений візит одразу в календарі з бейджем «Walk-in»; доступна дія «Почати».
- [ ] **WALK-BAR-03.** Барбер бачить **ціну послуги** на картці візиту (потрібна для оплати на місці; це не «фінанси мережі») і може позначити «Оплачено на місці (готівка/картка)» — за рішенням про оплату (відкрите питання).

## Admin

- [ ] **WALK-ADM-01.** У календарі мережі: клік по вільному слоту → «Створити візит (walk-in)» → та сама швидка форма.
- [ ] **WALK-ADM-02.** Оплата на місці: позначити «Оплачено (готівка/картка POS)»; чек Checkbox (PAY-ADM-04/07).
- [ ] **WALK-ADM-03.** Джерело візиту (`online` / `walk-in`) зберігається і видно в аналітиці — для оцінки каналів (розширення ANL).

## Відкриті питання

1. **Хто приймає оплату на місці**: барбер (позначає «оплачено») чи лише адмін. Рекомендація: **барбер може позначити** готівку/картку — інакше walk-in ламається операційно; суми і фінанси мережі барбер не бачить.
2. **Телефон клієнта**: обов'язковий (повний CRM, лояльність, відгуки) чи опційний (анонімні без бонусів). Рекомендація: **опційний у v1** — менше тертя в кріслі.
3. **KPI «частка walk-in»** (walk-in vs online): додавати в `analytics` чи ні — розширення ANL, не блокує фічу.
