# 16. Подарункові сертифікати

> Фіча: передплачені сертифікати на послуги — **гроші входять до послуги** (cash-flow наперед, високий інтерес перед святами). Сертифікат — **платіжний інструмент, не ціна і не знижка**: послуга коштує `AgreedPrice` (ADR 0006) як завжди, сертифікат лише **оплачує** `FinalPrice` (ADR 0013). Не комбінується з правилами знижок DSC-003 — ті застосовуються до ціни незалежно від способу оплати.
>
> Контексти: **`gift-certificates`** (новий, Supporting): випуск, код, баланс, погашення, строк дії; `billing` — сертифікат як **форма оплати** і чеки (продаж і погашення — різні чеки); `notifications` — доставка коду покупцю. Продаж: онлайн (картка) і на місці (готівка/POS). **Погашення в v1 фічі — на місці** (онлайн-погашення — розширення, див. «Відкриті питання»).

## Як течуть гроші і чеки (потік)

1. **Продаж**: `Payment` (картка онлайн або POS/готівка на місці) → **чек Checkbox #1** на позицію «Подарунковий сертифікат» — гроші увійшли (реалізація сертифіката = розрахункова операція; ДПС/практика ПРРО).
2. **Погашення на місці**: послуга завершується → **чек #2** на суму `FinalPrice` з фактичними формами оплати: сертифікат (частина або повністю) + картка/готівка (решта) — кілька форм оплати в одному чеку.
3. **Безкоштовний 7-й візит**: `FinalPrice = 0` → сертифікат **не списується**, чека немає (LYL-007 пріоритет, GFT-006).

> Бухгалтерська суть «сертифікат = передоплата» (офсет авансу при погашенні, чек #2 не створює другого доходу) — **перевірити з бухгалтером і Checkbox при інтеграції** (той самий захист, що LYL-007).

## Правило (спільне)

- [ ] **GFT-001.** Сертифікат: номінал (адмін-набір, за замовчуванням 500 / 1000 / 2000 грн), **унікальний код**, строк дії. Статуси: `active` → `partially_used` → `used` / `expired` / `cancelled`.
- [ ] **GFT-002.** Сертифікат **не ціна і не знижка**: `AgreedPrice` снепшотиться з `catalog` як завжди (ADR 0006); правила знижок (DSC-003, кап 30%) застосовуються до ціни незалежно; `FinalPrice` не змінюється від наявності сертифіката — сертифікат лише його оплачує.
- [ ] **GFT-003.** Погашення (v1) — **на місці**, повне або часткове; решта — картка/готівка. Працює для walk-in і для записаних візитів; отримувач може бути новим або анонімним клієнтом (семантика WALK-003).
- [ ] **GFT-004.** **Балансовість**: часткове використання зберігає залишок; одним сертифікатом можна оплатити кілька візитів, доки баланс > 0 і не вийшов строк.
- [ ] **GFT-005.** Строк дії — **12 місяців** з продажу (налаштовується, GFT-ADM-03). Після — не погашається (статус `expired`); політика повернення коштів — відкрите питання (ЗЗП).
- [ ] **GFT-006.** Безкоштовний 7-й візит — пріоритет (як DSC-005): `FinalPrice = 0`, списання сертифіката не відбувається.
- [ ] **GFT-007.** **Передаваність**: покупець ≠ отримувач; прив'язки до профілю при купівлі немає. Отримувач ідентифікується (телефон) лише на місці при погашенні — опційно.
- [ ] **GFT-008.** Скасування сертифіката адміном (втрата, шахрайство): з причиною, лог обов'язковий. Повернення залишку покупцю — ручна дія `billing` (політика — відкрите питання).

## Web (публічний сайт і кабінет)

- [ ] **GFT-WEB-01.** Публічна сторінка `/gift`: номінали, як це працює (3 кроки), CTA «Купити». Без логіну (покупець вводить телефон при оплаті).
- [ ] **GFT-WEB-02.** Купівля: номінал → оплата карткою (еквайринг, той самий ACL, що фаза 8) → код видано одразу на екрані + надіслано покупцю (SMS/push).
- [ ] **GFT-WEB-03.** Кабінет: секція «Мої сертифікати» — коди, залишки, строк дії (сертифікати, куплені цим `User`).

## Барбер (mobile)

- [ ] **GFT-BAR-01.** У візиті доступна позначка «Оплачено сертифікатом (код)» — так само, як оплата на місці (WALK-BAR-03): барбер суми мережі не бачить; валідація коду і залишку — серверна.

## Admin

- [ ] **GFT-ADM-01.** Список сертифікатів: фільтри (статус, номінал, період продажу); колонки: Код | Номінал | Залишок | Продано | Строк дії | Статус.
- [ ] **GFT-ADM-02.** Ручний випуск на місці: номінал → оплата готівка/POS → чек #1 → код (видрук/пошта/SMS). Семантика оплати на місці — WALK-ADM-02.
- [ ] **GFT-ADM-03.** Налаштування: набір номіналів, строк дії (місяці).
- [ ] **GFT-ADM-04.** Скасування сертифіката (GFT-008) — confirmation з причиною, лог.
- [ ] **GFT-ADM-05.** Статистика (розширення ANL): продано / погашено за період; **зобов'язання** — сума непогашених залишків (передоплати на балансі); **breakage** — прострочені невикористані залишки (фактична маржа).

## Відкриті питання

1. **Хто позначає погашення** на місці — барбер (як walk-in оплата, WALK відкрите питання 1) чи лише адмін. Рекомендація: барбер, суми не бачить.
2. **Повернення коштів за прострочений сертифікат** (ЗЗП, захист прав споживачів): дефолт «не погашається», перевірити з юристом до запуску фічі.
3. **Онлайн-погашення**: ввести код у флоу запису (оплатити депозит сертифікатом) — розширення після першого релізу фічі.
4. **Знижки на купівлю сертифіката** (передсвятові промо): не робити в v1 фічі; окрема фіча, не механіка DSC (сертифікат і так не знижка — GFT-002).
5. **Корпоративні сертифікати** (B2B, довільна сума, рахунок-фактура) — поза v1.
