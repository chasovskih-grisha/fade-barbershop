# 15. Публічна галерея робіт (before/after)

> Фіча: публічна галерея робіт — **до/після** і **AI-варіанти з реальним результатом** по кожному барберу, на сайті і в додатку, з **згодою клієнта**. Головний конверсійний інструмент барбершопу: записуються до того барбера, чию роботу бачать. Сировина вже збирається: AI-фото (02), референси (03), фото відгуків (06).
>
> Контексти: **`portfolio`** (новий, Supporting): елементи галереї, згода, статуся публікації; `scheduling` надає візити, `haircut-ai` — AI-варіанти, `feedback` — фото відгуків, `content` — місце на сайті, `notifications` — запит згоди після візиту.

## Правило (спільне)

- [ ] **PRT-001.** Елемент галереї = **пара «до/після»** (до = фото клієнта до стрижки або AI-варіант, який клієнт вибрав; після = фото результату) **або** одиночне «після». Кожен елемент: барбер, послуга, візит (посилання), дата, опційний опис.
- [ ] **PRT-002.** **Згода обов'язкова, двошарова**: (1) **клієнт** — opt-in («Опублікувати фото цієї роботи в галереї?», з варіантом анонімно — без обличчя); (2) **адмін** — підтверджує публікацію (модерація). Немає згоди клієнта — елемент не існує; авто-публікації немає.
- [ ] **PRT-003.** Джерела: (а) фото «до» з крісла + «після»; (b) AI-варіант з референсу (02) + фото результату; (c) фото з відгуку (06) — за окремою згодою. Галерея росте з існуючих потоків, окремого знімання не вимагає.
- [ ] **PRT-004.** Хто додає: барбер — у кріслі (PRT-BAR-01), адмін — з картки візиту. Хто бачить: адмін — усе; клієнт — статус свого елемента; публіка — лише опубліковане.
- [ ] **PRT-005.** Приватність: AI-фото і фото відгуків не копіюються в `portfolio` — лише посилання на джерело (інваріант 7); видалення джерела клієнтом (02/06) → елемент приховується і вимагає заміни фото або знімається.
- [ ] **PRT-006.** Життєвий цикл елемента: `pending_consent` (чекає клієнта) → `pending_review` (згода є, чекає адміна) → `published` / `hidden` (прихований адміном у будь-який момент). Відкликання згоди клієнтом → **миттєве** приховування + видалення за запитом.
- [ ] **PRT-007.** AI-елементи мічаються «AI-підбір → результат» з поясненням фічі і CTA «Спробувати» — галерея водночас маркетинг AI-підбору (02).
- [ ] **PRT-008.** Теги послуг (коротка/довга/борода/догляд) на елементі — для майбутніх фільтрів; самі фільтри й пошук по галереї — **пізніше**, не в першому релізі.

## Web (публічний сайт)

- [ ] **PRT-WEB-01.** Картка барбера на `/barbers` отримує мініатюри останніх робіт (3); клік — сторінка барбера.
- [ ] **PRT-WEB-02.** Сторінка барбера (`/barbers/{slug}`): сітка робіт (пари «до/після» зі слайдером), послуги барбера з цінами, кнопка «Записатися до цього барбера» → booking flow, крок 2 з предвибраним барбером.
- [ ] **PRT-WEB-03.** AI-елементи: підпис «AI-підбір → результат», коротке пояснення і CTA «Спробувати AI-підбір» → AI-флоу (фаза 10).

## Mobile (клієнт)

- [ ] **PRT-MOB-01.** У флоу запису (крок 2, вибір барбера) і в профілі барбера: вкладка «Роботи» — та сама галерея з того самого API, що і сайт (content OHS).

## Барбер (mobile)

- [ ] **PRT-BAR-01.** Після завершення візиту (під час `complete` або одразу після): «Додати до галереї» — фото «до» і «після» (камера), прив'язка до візиту, послуга підставляється.
- [ ] **PRT-BAR-02.** Відмітка «клієнт згоден (у кріслі)» — фіксує усну згоду для адміна; **не публікація**: без подальшого opt-in клієнта (PRT-002) елемент не публікується.
- [ ] **PRT-BAR-03.** Свої елементи: список зі статусами (`pending_consent` / `pending_review` / `published` / `hidden`); приховувати свої елементи барбер може, публікувати — лише адмін.

## Admin

- [ ] **PRT-ADM-01.** Розділ «Галерея»: черга модерації (нові елементи зі згодою), всі елементи по барберах зі статусами і фільтрами.
- [ ] **PRT-ADM-02.** Модерація: прев'ю пари «до/після», джерело (візит, клієнт, AI-варіант/відгук), згода клієнта (коли, який варіант анонімності), публікувати / приховати / відхилити (з причиною барберу).
- [ ] **PRT-ADM-03.** Запит згоди: після `AppointmentCompleted` клієнту з фото-потенціалом — push «Опублікувати фото вашої нової зачіски?» з екраном згоди (так, анонімно / ні); без відповіді — `pending_consent` не тисне повторно.
- [ ] **PRT-ADM-04.** Клієнтський статус: клієнт бачить свої елементи і їх статуси в «Моїх візитах» → візит; може відкликати згоду (PRT-006).

## Відкриті питання

1. **Анонімізація**: кроп «без обличчя» — ручний інструмент адміна в першому релізі (достатньо), авто-кроп — пізніше.
2. **«До» як AI-варіант**: референс-варіант vs знімок «до» з крісла — підтримуються обидва (PRT-001); рекомендовано знімок з крісла + AI-варіант в описі.
3. **Ліміти**: до 2 фото «після» на елемент — стартове значення.
