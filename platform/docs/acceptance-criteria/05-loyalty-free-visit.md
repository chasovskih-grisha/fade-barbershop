# 05. Бонус «кожен 7-й візит — безкоштовно»

> Фіча: програма лояльності — кожен 7-й візит клієнта безкоштовний. Рішення засновника прийнято; ширші програми лояльності і абонементи лишаються поза scope (див. `docs/roadmap.md`).
>
> Контекст: **`loyalty`** (новий, Supporting). Лічильник спирається на події `scheduling` (`AppointmentCompleted`), безкоштовний візит відображається в `billing` (сума 0), про бонус сповіщає `notifications`. Модель лічильника, скидання і підписка на події — **ADR 0009**. Приймальні критерії: `02`/`04` не зачіпаються.

## Правило (спільне для всіх поверхонь)

- [x] **LYL-001.** Лічильник рахує **завершені** візити (`completed`). Скасовані і no-show візити не рахуються; перенесені — рахуються один раз при завершенні.
  - **Рішення (відкрите питання 1 закрито): рахуються всі завершені візити — один візит = один інкремент, без класифікації послуг.** Гоління, догляд, пакет — кожен завершений візит дає +1.
  - **Чому так**: класифікація «стрижка» вимагала б прапорця в `catalog` і правил для комбінацій/партій — складність заради мінімального ефекту; правило «кожен 7-й візит» простіше комунікувати без винятків; зловживання дешевими послугами блокується налаштованим порогом (LYL-ADM-01).
  - Відхилена альтернатива: «лише стрижки» через прапорець послуги — можна додати пізніше без зміни event-механіки (обробник `AppointmentCompleted` почне фільтрувати), якщо зловживання з'являться.
  - Партія «батько + син» — один візит = один інкремент (нога батька, PARTY-010).
- [ ] **LYL-002.** Коли клієнт завершив 6 візитів, що рахуються, — наступний візит безкоштовний (показ прогресу «X/7»; на 6/7 — «Наступний візит безкоштовно»).
- [ ] **LYL-003.** Після завершення безкоштовного візиту лічильник скидається і цикл починається заново: безкоштовними є 7-й, 14-й, 21-й… візити.
- [ ] **LYL-004.** Безкоштовний візит — сума **0 грн** за всі послуги візиту; оплата клієнту не пропонується; бонус не комбінується зі знижками (`FinalPrice = 0` незалежно від застосовних знижок, див. `07-discounts.md` DSC-005).
- [ ] **LYL-005.** Візит стає безкоштовним автоматично, без участі барбера чи адміна: при записі 7-го візиту система показує «Безкоштовно» до підтвердження.
- [ ] **LYL-006.** Якщо клієнт скасовує безкоштовний візит — право на бонус зберігається для наступного запису; лічильник не змінюється.
- [x] **LYL-007.** Фіскальний чек на безкоштовний візит **не формується**: безоплатне надання послуги (0 грн) не є розрахунковою операцією (Закон № 265/95-ВР, ст. 2 — розрахункова операція = приймання коштів від покупця), тому РРО/ПРРО не застосовується і `FiscalReceipt` не видається (позиція ДПС ЗІР 109.02; практика: безоплатна передача в межах акції через ПРРО не проводиться; Checkbox: чек — при прийманні коштів). **Узагальнення (PAY-003)**: правило виведене з суми `FinalPrice = 0`, не з джерела — діє так само для 100% промокодів/правил (`full_discount_promo`, DSC-013) і будь-якого майбутнього механізму з нулем на виході.
  - Наслідок для платформи: `billing` не створює `Payment` і не викликає Checkbox на безкоштовному візиті; візит лишається в обліку (`scheduling`/`crm`), у «Оплатах» адміна видно запис 0 грн з причиною `loyalty` (LYL-ADM-05).
  - Виняток: якщо клієнт на цьому візиті оплачує додаткову послугу — чек формується лише на оплачену частину.
  - **Для бухгалтера — намірений обліковий treatment безкоштовного візиту** (фінальне рішення за бухгалтером при інтеграції):
    - **Дохід не визнається**: розрахункової операції немає (LYL-007 вище) — безкоштовний візит не створює ані доходу, ані receivable; визнавати роздрібну ціну як дохід і симетричну «знижку» як витрату не потрібно.
    - **Вартість відноситься на маркетингові витрати**: програма лояльності — маркетинговий інструмент утримання клієнтів, тому собівартість наданої послуги (час барбера, матеріали) відноситься на витрати на збут/маркетинг періоду, в якому візит відбувся. Це витрата **того самого періоду**, не зобов'язання перед клієнтом: ані грошей, ані авансу ми не отримували — у лояльності немає «відкладеного доходу» на відміну від сертифіката (ADR 0013: сертифікат = передоплата і зобов'язання до погашення).
    - **Джерело даних для обліку**: історія безкоштовних візитів в адмінці (LYL-ADM-04) з роздрібною ціною — снепшот `AgreedPrice` на момент запису (ADR 0006); періодична сума цих снепшотів = орієнтир для віднесення на маркетингові витрати.
    - **100% промокоди** (`full_discount_promo`, DSC-013) — той самий намірений treatment (маркетингова витрата, не дохід); підтвердити з бухгалтером разом.
    - **Залежить від форми і режиму**: ФОП/ТОВ, єдиний податок/ПДВ змінюють деталі (для платника ПДВ безоплатне надання може кваліфікуватись як об'єкт оподаткування — перевірити окремо); платформа фіксує **дані**, рішення про проведення — за бухгалтером.
  - При інтеграції з Checkbox перевірити актуальність норми (законодавство/практика ДПС можуть змінитись).

## Web (кабінет клієнта)

- [ ] **LYL-WEB-01.** У профілі клієнт бачить прогрес бонусу «X/7» і коротке пояснення правила (укр.).
- [ ] **LYL-WEB-02.** При записі візиту, який стає 7-м, клієнт бачить «Цей візит безкоштовний» на екрані підтвердження; оплата не пропонується (PAY-WEB-02 не застосовується).
- [ ] **LYL-WEB-03.** У «Мої візити» картка безкоштовного візиту має позначку «Безкоштовно (7-й візит)» і суму 0 грн.
- [ ] **LYL-WEB-04.** Після завершення безкоштовного візиту прогрес оновлюється (0/7) без додаткових дій клієнта.

## Mobile — клієнт

- [ ] **LYL-MOB-02.** Push-сповіщення при досягненні 6/7: «Вітаємо! Наступний візит безкоштовний 🎉» (`loyalty` → подія → `notifications`).
- [ ] **LYL-MOB-03.** У картці майбутнього безкоштовного візиту видно позначку «Безкоштовно» і суму 0.

## Mobile — барбер

- [ ] **LYL-BAR-01.** У картці візиту барбер бачить позначку «Безкоштовно (7-й візит)», щоб не пропонувати оплату.
- [ ] **LYL-BAR-02.** Зарахування візиту в лічильник відбувається автоматично при завершенні (`complete`) — барбер не виконує жодних додаткових дій.
- [ ] **LYL-BAR-03.** Барбер бачить прогрес клієнта «X/7» у картці клієнта (для розмови про бонус) — за рішенням, опційно в v1.

## Admin

- [ ] **LYL-ADM-01.** Правило вмикається/вимикається; поріг налаштовується (за замовчуванням 7). Вимкнене правило — нові бонуси не видаються, видані лишаються дійсними.
- [ ] **LYL-ADM-02.** Список клієнтів з прогресом «X/7»; фільтр «близькі до бонусу» (6/7) — для комунікації.
- [ ] **LYL-ADM-03.** Адмін може скоригувати лічильник клієнта вручну (помилка обліку, компенсація); кожна корекція логується (хто, коли, причина).
- [ ] **LYL-ADM-04.** Історія виданих і використаних безкоштовних візитів видно в адмінці (клієнт, дата, візит, роздрібна ціна — снепшот `AgreedPrice`); це джерело даних для обліку маркетингових витрат (нотатка для бухгалтера — LYL-007) — експорт CSV опційно.
- [ ] **LYL-ADM-05.** Безкоштовний візит видно в «Оплатах» (0 грн, причина `loyalty`) і в картці візиту календаря.

## Відкриті питання

1. ~~**Що рахується** (LYL-001)~~ — **вирішено**: усі завершені візити, без класифікації послуг (див. LYL-001).
2. **Скоуп рахунку**: по мережі (клієнт збирає на будь-якій локації — за замовчуванням) чи по локації. Для CLT-01 різниці немає, рішення потрібне до другої точки.
3. **LYL-BAR-03** (прогрес у картці клієнта): вмикати в v1 чи пізніше.
