# Трейсабіліті: критерії → фаза → контекст → статус

> Матриця відповідності: кожен приймальний критерій трасується до **фази** `docs/roadmap.md`, **bounded context**-у і **статусу**. Критерій вважається готовим, коли закрита його фаза і виконані AC цієї групи.
>
> Для фіч з event-механікою секція може починатися з **«Потоки»** — ланцюг подій між контекстами з посиланнями на ADR (див. 05): це трасує не лише критерії, а й те, *як* вони досягаються. Коли критерій прийнятий індивідуально (перший `[x]` у правилах), його рядок отримує статус «прийнято» раніше за групу.
>
> ID-діапазони = усі критерії файлу в межах секції. «Фаза» — мінімальна фаза, коли критерій може бути прийнятий; примітки вказують додаткові залежності.

> **Примітка синхронізації (2026-09-19)**: Статуси "у роботі" відновлено для AC-груп, які мають хоча б один `[x]` чекбокс (згідно з правилом: перший `[x]` → «у роботі»). Це забезпечує відповідність з логікою статусів.
>
> **Ревізія (2026-09-23)**: усі рядки матриці мають рівно 5 колонок (Критерії / Контекст / Фаза / Статус / Примітка); статус виводиться з `[x]` у файлі AC групи (усі `[x]` → «прийнято», частина → «у роботі», решта → «—»). Звірено з `docs/acceptance-criteria/*` (межі діапазонів, статуси), `docs/adr/` (цитати) і беклогом — фантомних посилань немає.

## Статус групи

| Статус | Значить | Коли |
|--------|---------|------|
| `—` не розпочато | Усі критерії групи `[ ]` | за замовчуванням |
| `у роботі` | Частина критеріїв `[x]` (рішення зафіксовані) або ведеться імплементація | при першому `[x]` |
| `прийнято` | **Усі** критерії групи `[x]` | коли закритий останній `[ ]` |
| `підтверджено` | Реалізація перевірена проти критеріїв (тести/приймання) | після імплементації фази |

Статус базується на чекбоксах критеріїв у файлі AC (`[x]` = прийнято). Оновлюється при зміні чекбоксів і при прийманні реалізації.

## 05 — Бонус «кожен 7-й візит» (`05-loyalty-free-visit.md`)

**Потоки** (події і стани між контекстами):

- **Лічильник** (частина A, ADR 0009): `scheduling.AppointmentCompleted` → outbox → `loyalty` (ідемпотентно за `AppointmentId`) → `counter += 1` (усі завершені візити — LYL-001; партія = +1 по нозі батька, PARTY-010) → на 6/7 → `FreeVisitGranted` → push «Наступний візит безкоштовно» (LYL-MOB-02).
- **Безкоштовний візит** (частина B): запис 7-го візиту → `scheduling` запитує активне право → `FreeVisitApplied` → `FinalPrice = 0` (LYL-004) → **без `Payment` і без чека** (PAY-003 + інваріант у `billing` README, LYL-007) → завершення → `FreeVisitUsed`, `counter = 0` → прогрес 0/7 (LYL-WEB-04, LYL-MOB-01/03).
