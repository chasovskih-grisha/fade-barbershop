# Клієнтський шлях (end-to-end)

> Один безперервний шлях клієнта крізь усі фічі платформи: від першого відвідування сайту до 7-го безкоштовного візиту. Кожен етап посилається на приймальні критерії (`acceptance-criteria/`), контексти і фази (`docs/roadmap.md`, `traceability.md`). Екрани: `docs/booking-flow.md`, `docs/admin-screens.md`.
>
> Мета: показати, що фічі з'єднуються в один флоу, — AI-фото стає референсом візиту, завершений візит запускає відгук і лічильник лояльності, а безкоштовний 7-й візит скасовує оплату і чек.

## Карта шляху

## Потік подій між контекстами

```
Гість → web: блог / локації / послуги
  → /login (OTP) → User (client) + ClientProfile (crm)
  → [опційно] AI-підбір (haircut-ai):
      SourcePhoto → згода → SuggestionGenerated → SelectedVariant
  → Запис (scheduling): service → [режим father-son] → barber → slot
      → Appointment або AppointmentParty (ADR 0011)
      → HaircutReference (+ AppointmentComment) на Appointment / PartyLeg
      → AgreedPrice (ADR 0006; на партії — на AppointmentParty)
  → Знижки (discounts): PromoCode/Rule/VIP → AppliedDiscounts → FinalPrice (ADR 0007)
  → Оплата (billing): PaymentInitiated → PaymentCaptured + ReceiptIssued
  → Очікування: push-нагадування (notifications)
  → Візит (scheduling): Confirm → Start → Complete
      ├─ AppointmentCompleted (outbox)
      │    ├─→ loyalty: counter +1 → на 6/7 FreeVisitGranted (push)
      │    └─→ feedback: відкривається вікно відгуку
  → Відгук: Rating + текст + FeedbackPhoto (feedback)
  → 7-й візит: FreeVisitApplied → FinalPrice = 0 → billing без Payment і чека
  → Після завершення 7-го: FreeVisitUsed → counter = 0 → цикл заново (14-й, 21-й…)
  → portfolio: запит згоди на фото роботи → opt-in + модерація → галерея барбера  Розгалуження:
  Слотів немає        → waitlist (WTL-001) → звільнення → SlotHold 15 хв → push → підтвердив → запис
  Не з'явився         → AppointmentNoShowed (NSH) → депозит утримано → 2 за 90 днів → повна передоплата
  Не був ≥ 60 днів    → winback-кампанія (WNB) → персональний промокод + push → повернення на етап 3/4
  Оплата сертифікатом → погашення на місці (GFT-003) → чек #2, сертифікат = форма оплати (ADR 0013)
  Привів друг → referral (RFR) → знижка другові на 1-й візит → після завершення — винагорода запрошувачу (ADR 0014)
```

## Етап 1 — Відкриття (гостьовий контур)

- Сайт: герой, локації, послуги з цінами по локації, блог (читається без логіну). Додаток: та сама стрічка блогу (`content`).
- **Живі слоти** (фаза 23): на `/services`, сторінці локації і барбера — «вільні вікна на 7 днів» прямо на сторінці; клік веде у флоу з повторною валідацією (`LST-001`).
- **SEO-сторінки послуг** (фаза 26): `/services/{slug}` з Schema.org і FAQ — пошук веде гостя одразу на сторінку послуги з ціною і CTA (до фази 26 — єдина сторінка `/services`).
- CTA запису веде до `/login` (якщо не авторизований). Ціни і доступність послуг — тільки активні, по локації (`MNG-ADM-10…12`).

## Етап 2 — Вхід

- Телефон + SMS OTP (ADR 0005): один `User` на web і mobile. При першому вході створюється `ClientProfile` (`crm`).
- Пароля немає; сесія web — cookie, mobile — bearer.

## Етап 3 — AI-підбір зачіски (маркетинговий крючок, опційно)

- Клієнт завантажує фото (web або mobile, камера/галерея) → **згода** на обробку AI (AI-WEB-02) → статус обробки (AI-WEB-03) → галерея **3–4 варіантів** (AI-WEB-04) → «Цей варіант» (AI-WEB-05). Ліміт 3 генерації на добу (AI-ADM-03).
- Результати зберігаються в історії клієнта; фото приватні (AI-WEB-08, ADR 0008). Відсоток з'являється в етапі 4 як джерело референсу.

## Етап 4 — Запис + референс + коментар

- Флоу: послуга → [режим, якщо `father-son`] → барбер → слот (деталі: `docs/booking-flow.md`, ADR 0011).
- Далі — зачіска: **«З AI-підбору»** (обраний варіант → `HaircutReference`), «Завантажити фото» або «Без референсу»; коментар ≤ 500 символів (REF-WEB-01…03).
- Підтвердження показує підсумок з мініатюрою референсу і коментарем (REF-WEB-03).
- `Appointment` несе: `ServiceId` + `AgreedPrice` + (опційно) `HaircutReferenceId` + `AppointmentComment` (ADR 0006, ADR 0007).

## Етап 5 — Знижка

- Клієнт вводить промокод (DSC-WEB-01…03) **або** знижка застосовується автоматично: перший візит (DSC-RULE-01), непікові години (DSC-RULE-02), VIP-рівень (DSC-VIP-01).
- Стекуються лише **VIP + промокод** (кап 30%); правила — одна найвигідніша (DSC-003); розбивка з кожною знижкою окремо — до підтвердження (DSC-006).
- `AppliedDiscounts` фіксуються при записі; `FinalPrice` ≥ 0 (ADR 0007).

## Етап 6 — Оплата

- **Депозит 30% `FinalPrice`** при записі (рішення); без успіху запис лишається «Очікує депозиту» (PAY-WEB-02). Ідемпотентність — подвійної оплати немає (PAY-WEB-03).
- Успіх депозиту: `PaymentCaptured` + `ReceiptIssued` (чек Checkbox на суму депозиту), посилання на чек (PAY-WEB-04); push про статус (PAY-MOB-04).
- **Решта (70%) — на місці після послуги**: картка через POS або готівка; сплата/повторна спроба — з картки візиту (PAY-WEB-01). Скасування за ≥ 4 год — депозит повертається; no-show — утримується (PAY-WEB-07).
- **Виняток — 7-й візит**: оплата не пропонується (LYL-WEB-02), чек не формується (LYL-007).

## Етап 7 — Очікування

- Push-нагадування перед візитом (мінімум, фаза 6). Статус і деталі — в «Мої візити».
- Референс і коментар можна змінити, **поки візит не підтверджений барбером** (REF-WEB-04, REF-MOB-02).

## Етап 8 — Візит

- Барбер у додатку: календар дня; картка візиту показує **референс (AI-фото або завантажене), оригінал фото і коментар** (REF-BARBER-01…03).
- Статуси візиту: `confirm → start → complete` (`scheduling`); no-show — окремо.
- `complete` публікує `AppointmentCompleted` через outbox → запускає етапи 9 і 10.

## Етап 9 — Відгук

- Push «Як пройшов візит?» (FDB-MOB-02); форма: оцінка 1–5 (обов'язково), текст ≤ 1000 символів, фото до 3 (FDB-001…005).
- **Вибір каналу** (фаза 24): у тому самому push — друга кнопка «Оцінити в Google» → GBP-сторінка локації (`GbpReviewUrl`); кнопки рівноцінні, без гейтингу (GBP-004) — клієнт обирає приватний або публічний канал сам.
- Один відгук на візит; вікно 30 днів (FDB-002/003). Барбер бачить свої відгуки з фото (FDB-BAR-01); адмін бачить усі (FDB-ADM-01).
- **Приватні в першому релізі (рішення, FDB-006)**: публікація на сайті — фаза 25 (`21-public-reviews.md`): згода клієнта + модерація адміна, бейдж «Підтверджений візит»; клієнт керує публічністю свого відгуку в «Моїх відгуках» (PUB-WEB-05). GBP-відгуки — окремий публічний канал, не синхронізуються з `feedback` (GBP-005).

## Етап 10 — Лояльність: прогрес

- `AppointmentCompleted` → `loyalty` інкрементує лічильник (ідемпотентно за `AppointmentId`, ADR 0009). Прогрес «X/7» — у профілі (LYL-WEB-01).
- На 6/7: `FreeVisitGranted` → push «Наступний візит безкоштовний» (LYL-MOB-02).

## Етап 11 — Безкоштовний 7-й візит

- При записі: бейдж «Цей візит безкоштовний» (LYL-WEB-02); `FreeVisitApplied` → `billing` рахує `FinalPrice = 0`; `Payment` і чек **не** створюються (LYL-004, LYL-007).
- Скасування безкоштовного візиту — право зберігається (LYL-006).
- Після завершення: `FreeVisitUsed` → `counter = 0` (ADR 0009) → цикл заново (14-й, 21-й…).

## Гілка: walk-in (живий запис на місці)

Альтернативний вхід у шлях — клієнт приходить без запису: барбер/адмін створює візит за ~10 секунд (WALK-001), без OTP і депозиту, оплата на місці (готівка/картка POS, чек Checkbox — WALK-004). З етапу 8 шлях сходиться: `start → complete` → події → відгук і лояльність (для ідентифікованих, WALK-003/005). Деталі: `acceptance-criteria/09-walk-in-booking.md`, `docs/barber-screens.md`.

## Гілка: waitlist (слотів немає)

Якщо на кроці 4 вільних слотів немає — замість відмови клієнт стає в **лист очікування** (WTL-001): конфігурація + вікно дат + точність. Звільнений слот (скасування або no-show) утримується soft-hold-ом 15 хв і пропонується першому в черзі (ADR 0012); підтвердження повертає клієнта на етап 5 (знижки → оплата → звичайний запис). Пропуск/прострочення → слот іде наступному; 3 несправності поспіль → пауза. Деталі: `acceptance-criteria/14-waitlist-autofill.md`.

## Гілка: no-show

Клієнт не з'явився і не скасував → через 15 хв візит фіксується автоматично (`AppointmentNoShowed`, NSH-001): депозит утримується (без ручної дії, NSH-003), лояльність не рахує (інваріант 9), аналітика підвищує rate (ANL-004). 2 no-show за 90 днів → наступні записи лише з повною передоплатою (NSH-006); один успішний візит знімає обмеження. Шлях поновлюється з етапу 2 (нова запис). Деталі: `acceptance-criteria/12-no-show-policy.md`.

## Гілка: подарунковий сертифікат

Покупець (не обов'язково майбутній клієнт) купує сертифікат на `/gift` без логіну — код видано одразу і надіслано SMS/push (GFT-WEB-01/02). Отримувач записується як завжди або приходить як walk-in; на місці називає код → частина або весь `FinalPrice` оплачується залишком сертифіката, решта — картка/готівка (GFT-003, чек #2, ADR 0013). Сертифікат — не знижка: знижки застосовуються до ціни як завжди (GFT-002); безкоштовний 7-й візит сертифікат не списує (GFT-006). Баланс живе до строку — одним сертифікатом кілька візитів (GFT-004). Деталі: `acceptance-criteria/16-gift-certificates.md`, `docs/gift-certificates.md`.

## Гілка: referral («приведи друга»)

Клієнт ділиться персональним кодом/посиланням з кабінету (RFR-WEB-01). Друг реєструється → атрибуція фіксується (`ReferredBy`, останній торк 30 днів, імутабельно) → при записі referral-знижка застосовується автоматично, заміщуючи правило «Перший візит» (етап 5). Після завершення візиту друга (етап 8) запрошувач отримує винагороду — знижку на наступний візит (90 днів) + push. Анти-аб'юз: нагорода лише за перший завершений візит нового клієнта; 2 no-show поспіль → ануляція (RFR-005). Деталі: `acceptance-criteria/17-referral-program.md`, `docs/referrals.md`.
