# T-4615b · Запис читає каталог, не JSON

- **Stage**: M1 (phase 2) · **Tags**: backend, catalog · **Complexity**: middle · **Depends on**: T-4615a
- **StoryPoints**: 5

## What

Прибрати третє меню. `StaticServiceRepository` читає `booking/data/services.json` і віддає один список на будь-яку локацію. Поле локації в методі не використовується.

Після слайсу крок вибору послуги бере `Service` і `ServicePrice` з каталогу:

- вимкнена послуга не показується ніде;
- послуга без активної ціни в цій локації не показується в цій локації;
- ціна на картці — ціна локації, не число з файлу;
- тривалість — з каталогу, включно з `parallelDuration` для пакета.

Файл `services.json` не лишається запасним джерелом. Якщо каталог порожній, крок показує порожній стан, а не зашитий прайс.

Уже створені візити цей Slice не переоцінює.

## Why

Інакше адмін вимикає послугу, а гість усе одно записується на неї з файлу. Два прайси не можна пояснити ні клієнту, ні касі.

## Done

- [ ] Вибір послуги в записі не читає JSON
- [ ] Вимкнена послуга і послуга без ціни локації відсутні в списку цієї локації
- [ ] Порожній каталог дає порожній крок, не демонстраційний прайс
- [ ] Тест: дві локації з різними цінами показують різні суми
- [ ] Існуючий візит зберігає свій `AgreedPrice` після зміни прайсу (регрес, механізм лишається в T-024)

## Risks

- [ ] **Демо-сіди.** Якщо e2e годувалися лише JSON, вони мають сіяти послугу в каталог. Тихий фолбек на файл заборонений
- [ ] **Подвійний список на сайті.** Публічні сторінки послуг теж читають каталог. Якщо якийсь екран лишився на JSON, це дефект слайсу, не окрема задача
