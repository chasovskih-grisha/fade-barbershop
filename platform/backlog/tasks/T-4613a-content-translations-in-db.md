# T-4613a · Переклад каталогів і контенту: одна таблиця `Translation`, zod-контракти, фолбек на `uk`

- **Stage**: M1 (phase 3) · **Tags**: backend, i18n, content, data · **Complexity**: complex · **Depends on**: T-4612, T-031, T-024
- **StoryPoints**: 8

## What

T-4612 зафіксувало правило «контент ≠ ключі» (назви послуг, статті, імена — дані, а не інтерфейс). Цей Slice дає цим даним **переклад**, інакше перемикач з T-4613d показує англійське меню з українськими послугами.

Одна таблиця на всі сутності й усі мови (ADR 0053 §5):

```
Translation(id UUID, entityType String, entityId UUID, locale String, values Json, createdAt, updatedAt)
@@unique([entityType, entityId, locale])
```

- `entityType` — закритий перелік `service | location | article` **у `packages/contracts`** (не в API і не в базі), бо клієнти мають залежати від контрактів (AGENTS.md);
- `locale` — `String` (BCP-47), **не enum**: третя мова не має вимагати міграцію типу;
- `values` — типований об'єкт полів, **валідований zod-схемою** на кожен `entityType` (`zod` додається в T-4612a):

| `entityType` | Поля в `values` | Джерело |
|--------------|----------------|---------|
| `service` | `name`, `description` | `Service:249` |
| `location` | `name` | `Location:125` |
| `article` | `title`, `excerpt`, `body`, `tags` | `Article:292` |

**Чому одна таблиця, а не три** (`ServiceTranslation`/`LocationTranslation`/`ArticleTranslation`): вона розмножується на кожну перекладабельну сутність і знову прив'язує схему до набору мов. Тут **нова мова = один рядок на сутність, нуль міграцій**; нове поле = нуль міграцій (JSON). Альтернативи (EAV-рядок на поле, JSONB-колонка в сутності) — у ADR 0053.

**Фолбек — єдине правило резолву:** запит за перекладом locale → none рядка → `uk` → none (контент не перекладено) → `null`, і публічний DTO повертає `uk` як локаль, щоб клієнт знав, що бачить сав-контент. Ніколи не порожній рядок, ніколи не 404. Фолбек живе в репозиторії, а не в клієнті — інакше правило розійдеться між `web`, `shop` і `admin`.

**API:** публічні ендпоінти каталогу/локацій/контенту приймають `?locale=uk|en` (типований, з валідацією; невідома локаль → `uk` + 400-ніс, не мовчки), DTO несе `contentLocale`, щоб клієнт міг показати фолбек чесно. Контракт у `packages/contracts`, не DTO всередині API (AGENTS.md). Адмін-API — окремий CRUD перекладів (редагування — T-4613b).

**Чистий доступ.** `entityId` поліморфний, тому DB не забезпечує FK. Компенсація — порт `TranslationRepository` у кожному контексті (`catalog`, `locations`, `content`) і zod-валідація `values` на вході: помилка стає відмовою на запис, а не тихим рядком. Спільна таблиця — свідоме послаблення правила «контексти не ділять таблиці», зафіксоване в ADR 0053 §5.

**Не перекладається:** `User.name` (ім'я барбера, `schema.prisma:16` — персональні дані людини), адреси, телефони, `Article.slug` (у URL, лишається латиницею). Правило з ADR 0053 §5, дублюється в code-review чекліст, а не вгадується.

## Why

Блог (`T-031`) — головний organic-канал для іноземних клієнтів; без перекладу статті english-версії не існує фізично. Каталог послуг — те, що порівнюють перед записом. Це сховище, а не UI: воно визначає, чи зможе перемикач (T-4613d) показати щось інше, крім українського. Вимога засновника «не обмежені мовами» — саме про це: зараз `en`, але `pl`, `de` чи RTL не мають вимагати міграції.

## Risks

- [ ] **Одна таблиця без FK** — видалення сутності не прибирає переклади; нужен явний cleanup (каскад у сервісі або cron-збирання), інакше таблиця повільно заростає сиротами
- [ ] **`values Json` — помилка не видно в схемі DB**: без zod на вході можна записати `{name: 42}` або поле чужого `entityType`; тому zod-валідація — обов'язкова частина запису, а не «потім додамо»
- [ ] **Спільна таблиця для трьох контекстів** послаблює правило «контексти не ділять таблиці»; компенсується портами, але при рев'ю треба перевіряти, що контекст не пише чужі `entityType`
- [ ] **`article.body` на реальних даних** — migration мусить бути online-сумісною (новий стовпчик = нові рядки `Translation` з `uk` з існуючих `Article`), а не «вимкнути й перелити»
- [ ] **Фолбек, схований у клієнті** → `web` і `shop` показують різне; репозиторій — єдине місце
- [ ] **Переклад як колонка `*En`** або як окрема таблиця на сутність — відхилено в ADR 0053; рев'ю має це ловити
- [ ] **Імена барберів у ключах** → персональні дані + зламана мультилокаційність; тест на відсутність `User.name` у перекладі
- [ ] **`locale` як enum** → третя мова = migration; лишаємо `String` з валідацією на рівні домену
