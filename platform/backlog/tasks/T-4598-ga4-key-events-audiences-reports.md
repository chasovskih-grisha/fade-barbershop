# T-4598 · GA4 key events, аудиторії та звіти

- **Stage**: M3 (phase 14 — аналітика) · **Tags**: analytics, marketing, conversion, qa · **Complexity**: middle · **Depends on**: T-4594, T-4596, T-4597
- **StoryPoints**: 5

## What

Перетворення подій на рішення: маркування key events, побудова аудиторій (для ставок і оцінки якості трафіку) та мінімальний набір звітів, який засновник відкриває в понеділок.

### Key events (маркуються в адмінці GA4)
| Key event | Подія | Обґрунтування | Ціль для Google Ads |
| --- | --- | --- | --- |
| `booking_confirmed` | бронювання створено | головна бізнес-конверсія | `Booking` (in-app) |
| `payment_captured` | депозит/оплата отримана | фактична виручка, гірша за бронювання | `Purchase` value-based |
| `auth_otp_verified` | клієнт ідентифікований | health-check воронки + ретаргетинг на «записався, але не прийшов» | не для ставок, лише аудиторії |
| `phone_click` | клік по телефону | offline-конверсія, недоступна якнайінакше | `Call now`/offline action |

**Чому тільки чотири**: Google Ads дає ~8 конверсій на аккаунт за замовчуванням, кожна конкурує за вагу. Решту подій (кроки воронки, перегляди) key events **не** є.

### Аудиторії (4, на базі GA4-сигналів, без PII)
| Аудиторія | Визначення | Навіщо |
| --- | --- | --- |
| `abandoned_booking_7d` | `booking_started` без `booking_confirmed` за 7 днів | знайти, де ламається флоу; ретаргетинг «ви не дозаписали» |
| `booked_no_deposit_24h` | `booking_confirmed` без `payment_captured` за 24 год | операційний сигнал (оплата не пройшла) + аудиторія «прийди й оплати» |
| `lapsed_90d` | `page_view` ≥ 3, жодного `booking_confirmed` за 90 днів | хто ще не клієнт — для активації |
| `otp_no_booking_7d` | `auth_otp_verified` без `booking_confirmed` за 7 днів | втрачений через ідентифікацію клієнт |

Обмеження, які треба зафіксувати в описі кожної: при `ad_user_data = denied` (типово) аудиторії **не** можна експортувати в Ads/CRM і не можна використовувати для Customer Match — лише в межах Google (ставка, звітність).

### Звіти (5, у вигляді збережених конфігурацій)
1. **Acquisition** — `session_source`/`session_medium` → `page_view` → `booking_confirmed` → `payment_captured`, з `utm_content` (окремий сегмент `direct` за T-053).
2. **Форонка запису** — Explore: кроки 1→6 у порядку, розрізнення за `entry_point` і `location_code`.
3. **Локації/послуги/барбери** — `booking_confirmed` і `booking_value` за `location_code` / `service_id` / `barber_id`.
4. **Дзвінки vs записи** — `phone_click` vs `booking_confirmed` за тиждень.
5. **Реалtime-панель для запусків** — швидка перевірка «живе чи ні» під час рекламних спостережень (T-4531).

## Why

Замір — це не «дані в GA4», а відповідь на питання «куди перелити гроші». Key events і аудиторії — це те, що робить GA4 керованим: без них Google оптимізує під клік по телефону з лендинга й не знає, що такий клік не конвертується. При цьому надлишок конверсій гірший за їхню відсутність.

## Risks

- [ ] **Key event без даних**: GA4 не маркує подію, яка ще не надходила 24 год — спланувати заздалегідь
- [ ] **Export audience → відмова**: спроба вивантажити аудиторію в Ads з `denied`-консентом впаде; не намагатися «обійти», а зафіксувати обмеження
- [ ] **Аудиторії з малих вимірок**: при <1000 записів/міс аудиторії непридатні для ставок — скористатися лише діагностикою
- [ ] **Зміна моделі конверсій** після запуску Ads знецінює історичні ставки — рішення раз, до старту реклам
