# T-004 · Design System: Tokens and Component Core

- **Stage**: M0 (phase 0, in parallel with phases 1–2) · **Tags**: frontend · **Complexity**: middle · **Depends on**: T-001 (пакети монорепо); ~~T-003~~ — **removed** (FADE approved 2026-09-16, palette fixed 2026-09-18: monochrome-first, `brand/color-type.md`)
- **StoryPoints**: 5

## What

Специфікація — `docs/design-system.md`. Імплементація:

- `packages/design-tokens` — single source (JSON → CSS-змінні web/admin, NativeWind-тема mobile): colors **already fixed** (`docs/design-system.md` §Токени: Night `#0E0E10`, Bone `#F4F4F6`, sіра шкала, `accent.blue` AI/focus — monochrome-first), fonts — **default Fixel Display + Fixel Text** (files in `brand/fade_01_kit/fonts/`, @font-face/expo-font — plan there as well; sтатуs «awaits founder confirmation» — after which it is removed without architectural change), spacing 4px, radii, semantic map of visit statuses.
- `packages/ui` — primitives + доменні patterns sтартового набору (Button, Field/OtpInput/PhoneInput, StatusPill, PriceBreakdown, SlotPicker, PhotoUpload, EmptyState, Table, CalendarDay/Week…) — each with full set of states (default…skeleton, error).
- Гейти: «hex у екранах perборонений — тільки токени» (stylelint/ESLint у CI), doc-sторінка/приклад на кожен компонент.
- 4 еталонні екрани в sиsтемі: головна web, shell адмінки, екран sлотів flow, головна mobile.

## Why

phase 2 (admin) і phase 3 (sайт) починають UI одразу per фазою 1 — без sиsтеми кожен екран винаходить кнопки і colors, і темний преміум-sтиль бренду розмиваєтьsя per 27 фаз. Компоненти виведені з реальних екранів (SlotPicker — flow perпиsу, PriceBreakdown — DSC-006, StatusPill — sтатуsи візиту), а не «бібліотека perради бібліотеки» (KISS/YAGNI — `engineering-principles.md`).
