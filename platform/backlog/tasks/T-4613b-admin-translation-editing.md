# T-4613b · Адмінка перекладів: редагування `en`, індикатор неповноти, сид контенту

- **Stage**: M1 (phase 3) · **Tags**: admin, i18n, content, frontend · **Complexity**: middle · **Depends on**: T-4613a, T-024, T-2400
- **StoryPoints**: 5

## What

T-4613a дав сховище перекладів; без цього слайса перекладати ніким і нічого. Засновник (не перекладач) редагує `en` там, де вже редагує `uk`.

**(1) Форми `en` у наявних екранах адмінки** — послуги (`ServiceManager`), локації, статті (`ArticleManager`): блок «English» поруч з українським, ті самі поля, `description`/`body` — rich text. Не окремий «екран перекладів»: це дві мови в одній формі, інакше редактор забуде про `en` і публікує українською. Форма пише через **спільний CRUD перекладів** з T-4613a (ключ — `entityType` + `entityId` + `locale`), а не через окремі ендпоінти на сутність: одна таблиця означає, що новий тип перекладабельної сутності додає форму, але не міграцію.

**(2) Індикатор неповноти.** Список послуг/локацій/статей показує «EN ✓ / EN —», фільтр «без перекладу». Тільки в адмінці: публікація не блокується (фолбек на `uk` працює, див. T-4613a), але неповний переклад **видимий**, інакше «англійський сайт» виявиться на launch тихо.

**(3) Сид поточного контенту.** Наявний `uk`-контент (послуги, локації, статті з T-031) переноситься в переклади `uk` (або лишається в основних полях як джерело — рішення фіксуємо в міграції T-4613a, тут лише інструмент сиду й перевірка, що жоден запис не лишився без перекладу для `uk`).

**(4) Локалізована сама адмінка — ні.** `admin.fade.com.ua` лишається `uk`: це внутрішній інструмент, перекладати його none сенсу, а T-4612a гейт поширюється на `apps/shop`/`apps/web`, не на `admin`.

## Why

Фолбек приховує діру: без індикатора `en`-сторінки з українським контентом виглядають робочими. Редактор має бачити, **що саме** ще не перекладено, до того, як на сайт прийдуть іноземці.

## Done

- [ ] Блок «English» у формах послуг, локацій, статей; збереження через спільний CRUD `Translation` (T-4613a) з ключем `entityType` + `entityId` + `locale`
- [ ] `description`/`body` — rich text, а не `textarea` (T-4529)
- [ ] Списки показують статус перекладу; фільтр «без перекладу»
- [ ] Публікація не блокується відсутністю `en` (фолбек), але статус видимий
- [ ] Сид/перевірка: кожен активний `uk`-запис має переклад `uk`, жоден не «зник» з каталогу
- [ ] `admin` лишається `uk`; гейт T-4612a не поширюється на `apps/admin`
- [ ] Tests: форма зберігає `en`, індикатор рахується, фільтр працює
- [ ] Перевірено в браузері: редагування uk/en поруч, довгий `en`-текст не ламає верстку таблиці
- [ ] `pnpm docs:validate` зелений

## Risks

- [ ] **Два редактори в одній формі** — легко перепутати поле; вимога: підпис локалі + прев `uk`/`EN`, а не колір
- [ ] **Блокування публікації без `en`** → власник не зможе опублікувати свіжу послугу; не блокуємо
- [ ] **Індикатор без фільтра** — непрактичний; разом
- [ ] **Переклад `admin`** розширить задачу на весь адмін-фронт без користі; зафіксовано як no
- [ ] **Rich text у двох мовах** — розбіжність форматування; спільний sanitizer, окреме зберігання
- [ ] **Одна таблиця ≠ один екран**: новий `entityType` додає форму й колонку в індикаторі, але потребує zod-схеми в `packages/contracts`; забути схему — значить отримати переклад у чужих полях
- [ ] **Значення приходять як `values Json`** — форма має рендерити поля за zod-схемою конкретного `entityType`, інакше редактор побачить сирі ключі замість полів форми
