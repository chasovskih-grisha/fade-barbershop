# T-4806a · Транспортні заголовки на шлюзі й скан Mozilla Observatory

- **Stage**: M3 · **Tags**: devops, security · **Complexity**: junior · **Depends on**: T-4806, T-4614a
- **StoryPoints**: 2

## What

Дві перевірки, які не живе в коді застосунків: (1) HSTS і супутні заголовки віддає шлюз на
публічному домені, зокрема для статики, яку Next не обробляє; (2) скан Mozilla Observatory на
публічному URL дає A+ і його результат збережено в документації релізу.

## Why

T-4806 закриває CSP із nonce у `apps/web`/`apps/admin`. Але «A+ в Observatory» і «заголовки на
API gateway» перевіряються лише на живому домені: у репозиторії немає ні публічного URL, ні
конфігурації шлюзу, тож тримати їх у T-4806 означало б закрити задачу з неперевіреними пунктами.
Прод-образи й автодеплой — T-4614a; без них скану нема на чому бігти.

## Sources

- T-4806; `docs/security-hardening.md`
- `infra/` — конфігурація шлюзу

## Done

- [ ] Публічний домен віддає HSTS (≥ 6 місяців, `includeSubDomains`, `preload`) і `X-Content-Type-Options` на всіх відповідях, включно зі статикою
- [ ] Mozilla Observatory: A+ на публічному URL, скріншот/посилання в документації релізу
- [ ] CSP не блокує жодного легітимного скрипта (перевірка в браузері на живому домені)

## Blocking evidence (2026-11-26)

`T-4614a` (прод-образи) і `T-4614c` (автодеплой) — `review`, публічного домену з цим кодом ще
немає; у репозиторії відсутня конфігурація API gateway (`infra/` містить лише docker-compose для
локального стеку). Скан Observatory запускається тільки проти публічного URL, тому пункт «A+»
фізично не перевіряється на цьому коміті. Розблоковує: пуш T-4614a/T-4614c у прод і один прогін
скана на домені.
