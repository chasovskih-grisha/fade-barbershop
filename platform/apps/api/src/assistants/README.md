# Асистенти (`assistants`)

> Тип піддомену: **Supporting**. ADR 0020. Поза v1 (M7, фаза 28).

LLM-шар поверх готових контекстів: оркестратор обирає агента за наміром, агент кличе **наявні use cases** через порти. Домен тут не повторює правила слотів, цін і знижок — він тримає лише діалог.

## Ubiquitous language

- **Agent** — роль у діалозі, не працівник: `client` (консьєрж клієнта), `analyst` (питання засновника до даних), `ops` (підказки барберу й адміністратору).
- **AgentChannel** — джерело вводу: `web`/`mobile` (клієнтські поверхні), `admin`. Роль приймає репліки лише зі свого каналу.
- **AgentMessage** — одна репліка діалогу: роль, канал, текст ≤ 2000 символів, час.
- **AssistantConversation** — агрегат діалогу: стек реплік, статус `open`/`closed`, межа `lastMessageId`. Повторна доставка повідомлення за `id` не додає репліку (ADR 0009/0016).
- **AgentTurn** — метадані ходу агента: канал, час, намір-кандидат (`null` — класифікатор ще не відповів).
- **Intent** — нормалізована мітка наміру (`book_slot`). Класифікація — в домені, не в промпті (ASSIST-001).
- **AgentLog** — журнал викликів інструментів (хто, коли, який порт, який результат) — слайс T-280b.

## Межі

- Імпортів Nest/Prisma/HTTP у `domain/` немає; зовнішній LLM — лише через порт `LlmClient` з фейком у dev (ASSIST-003).
- Між агентами — події через outbox, не прямі виклики (ASSIST-004).
- Грошові дії та підтвердження запису — лише після явного підтвердження клієнта в діалозі (ASSIST-006).
