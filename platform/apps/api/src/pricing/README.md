# Surge-ціноутворення (T-4811)

Множники ціни за годиною/днем тижня й рівнем барбера. Правило зберігається в
`SurgeRule`, застосовується при створенні запису й фіксується на `Booking`
(`surgeBasisPoints`, `surgeRuleId`) — ціна візиту не рухається пізнішими
змінами правил (ADR 0006).

- **Матчинг**: специфічніше правило перемагає (локація > рівень > день >
  вікно), за рівної специфічності — вищий множник. Мережеве правило має
  `locationId = null`. Правило ніколи не знижує ціну: множник ≥ 10000 bp.
- **Математика**: базисні пункти, цілі копійки (`applySurge`), без float.
- **Адмін**: `GET /admin/pricing/surge-rules?locationId=…`,
  `PUT /admin/pricing/surge-rules` (`id` — заміна, без `id` — створення).
  Валідація: день 0..6, вікно 0 ≤ from < to ≤ 1440 (пара разом), рівень із
  `junior|middle|senior|top`, множник 10000…50000 bp.
- **Runbook**: (1) `pnpm --filter api db:migrate`; (2) створити правило
  `PUT` з `locationId` локації (або без — мережеве); (3) перевірити ціну в
  слоті після `SurgePricing.quote` (множник у відповіді й у снепшоті запису);
  (4) якщо клієнт бачить стару ціну — перевіряти `Booking.surgeBasisPoints`,
  а не поточні правила.
- **Не покрито тут**: екран адмінки й повідомлення клієнту про surge —
  фронтенд-лейн; occupancy-based множники (потребують живої статистики
  завантаження) — наступний слайс.
